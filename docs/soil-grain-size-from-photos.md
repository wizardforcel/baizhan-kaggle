# Soil Grain Size From Photos Writeup

## 一、比赛简介

### 1.1 背景
我们参与的是 Kaggle 比赛 Predicting Soil Grain Size Distributions from Images。该比赛要求从土壤表面照片推断其质量粒径分布。训练集包含 24 个不同土壤样本，共 127 张训练照片，测试集包含 10 个土壤样本，共 35 张照片，全部照片总数为 162 张。每个土壤样本只有一个真实的累积粒径曲线，多张照片仅用于提供不同视角和拍摄条件。换句话说，样本的真正独立数量不是照片数量，而是样本数量：24 个土壤样本才是 24 个独立标签，127 张照片只是这 24 个标签的多次观测，这一点直接决定了我们的验证方案必须按样本或地点分组，而不能按照片随意划分。

数据采集设备存在明显差异，训练照片由 Motorola 和 Samsung 手机拍摄，测试照片则来自 iPhone。这种设备差异导致 JPEG 压缩、色彩处理和镜头特性不同，纹理外观会发生系统性变化。更重要的是，训练照片在预处理阶段被统一降采样到大约 4.6 像素/毫米并以约 75 的质量系数保存为 JPEG，而测试照片是 14～20 像素/毫米的高分辨率原图，质量系数约 94。同一个土壤在训练集和测试集中看起来完全不同，如果我们不做任何对齐，直接交给模型，模型很容易把"分辨率差异"误当成"土壤差异"。另外，可见表面纹理与实验室筛分测得的质量分布并非一一对应，特别是在细粒端，肉眼难以分辨单个颗粒，模型必须从统计纹理推断级配曲线。

比赛背景论文和描述指出，累积分布在对数直径轴上呈现平滑单调特性，且不同土壤的 D50 跨越多个数量级。训练曲线几乎都在 63 mm 处接近 100%，也就是说训练集几乎不含卵砾石，而某个测试样本却布满了 60～150 mm 的大石块，这完全超出了训练分布的范围。我们需要在这种跨设备、跨尺度、分布外大颗粒的条件下实现泛化，这也是后面专门引入 SAM 粗颗粒测量的原因。

### 1.2 目标
我们的目标是为每个土壤样本预测 11 个粒径支点上的累积质量百分比。

```python
SUPPORT = np.array([0.002, 0.0063, 0.02, 0.063, 0.2, 0.63, 2.0, 6.3, 20.0, 63.0, 200.0])
# 11 个粒径支点，单位是毫米，从小到大覆盖黏土到砾石
# 每个支点上的值表示"细于该直径的质量占总质量的百分比"
```

预测曲线必须满足物理约束：单调不减、取值在 0 到 100 之间、最后一列固定为 100%。例如在 0.063 mm 处预测值为 60%，表示约 60% 的质量细于该直径。输出格式与 sample_submission.csv 保持一致，即每行是一个 sample_id，后面跟着 11 列数值。任何一个样本被漏掉或格式错误，整份提交可能都无法参与评分。

### 1.3 评价标准
官方评价指标为 Earth Mover Distance，其对数加权形式与我们本地代理误差一致。直观来说，官方指标就是真曲线与预测曲线之间在对数粒径轴上的面积差，对数间隔越大的区间权重越大。这意味着在 20 mm 和 63 mm 处犯的错，跟黏土端犯的错一样贵，粗砾石端绝不是可以被忽略的"少数派"。我们使用对数间隔权重近似。

```python
import numpy as np

SUPPORT = np.array([0.002, 0.0063, 0.02, 0.063, 0.2, 0.63, 2.0, 6.3, 20.0, 63.0, 200.0])
W = np.diff(np.log10(SUPPORT))  # 11 个点围出的 10 个对数间隔宽度，作为权重

def emd(true, pred):
    # 计算加权 L1 差异，忽略最后一列常数 100
    return float(np.mean(np.abs(np.asarray(true)[:, :-1] - np.asarray(pred)[:, :-1]) @ W))

def fix(p):
    # 保证单调性和上界，防止预测出现下降
    p = np.maximum.accumulate(np.clip(np.asarray(p, dtype=float), 0, 100), axis=1)
    p[:, -1] = 100.0
    return p
```

分数越低越好。我们的初始基准提交得分为 75.52636，经过特征工程和模型融合后，最终第七版提交得分为 36.03689，分数几乎下降了一半以上。整个过程中我们还记录了大量失败实验，它们和成功实验一样有价值。

```python
import pandas as pd

def toks(s):
```

### 2.2 数据清洗

```python
def contains(seq, sub):
    n = len(sub)
    return n > 0 and any(seq[i:i + n] == sub for i in range(len(seq) - n + 1))

def match_id(key, lookup):
    kt = toks(key)
    hits = [(len(k), v) for k, v in lookup.items() if contains(kt, k)]
    if not hits:
        return None
    m = max(h[0] for h in hits)
    best = {v for l, v in hits if l == m}
    return best.pop() if len(best) == 1 else None
```

我们统一物理尺度，将所有图像重采样到相同的像素/毫米基准，避免设备差异干扰纹理。这里的关键做法是"把测试照片压到训练照片的样子"，而不是反过来试图"还原"被破坏的细节：训练照片普遍比测试照片分辨率低，我们需要下采样到最粗相机的尺度，并且把测试图片按训练照片的 JPEG 量化表重新编码一遍。这样做的理由是，细尺度纹理大约在毫米级别，它与分辨率和 JPEG 块效应强相关，与其去猜测压缩前的模样，不如让两边经受同样的退化。凡是锐度超过 6 像素/毫米的照片都走这条 train-like 路径，最终统一到 4.5 像素/毫米。

### 2.3 训练调参
我们先实现 DoG（高斯差分）纹理特征，参考公开方法，用多尺度高斯差捕捉颗粒边缘。所谓 DoG，就是用 σ = 0.25, 0.5, 1, 2, 4, 8 mm 的一组高斯模糊对图像做逐级平滑，相邻两级相减得到的差图即可看作"该尺度下剩下的纹理能量"，再除以整图标准差来消除曝光和对比度差异，最后取对数。这样每张照片只得到 5 个数，却把它在大尺度与小尺度上的纹理强弱都概括进去了，等于在图像空间里做了一次"筛分"。

```python
SIGMAS = np.array([.25, .5, 1., 2., 4., 8.])

def dog_vector(image, ppm):
    # DoG 特征，用于捕捉不同尺度的颗粒纹理
    gray = np.asarray(image.convert("L"))
    factor = 4.5 / ppm
    gray = cv2.resize(gray, (round(gray.shape[1]*factor), round(gray.shape[0]*factor)))
    smooth = [cv2.GaussianBlur(gray, (0,0), float(s*4.5)) for s in SIGMAS]
    # 计算相邻高斯差的标准化标准差
    feats = []
    for a, b in zip(smooth[:-1], smooth[1:]):
        feats.append(np.log(float(np.std(b-a))/(float(gray.std())+1e-6)+1e-6))
    return np.array(feats)  # 5 维
```

特征提取后我们按地点做 GroupKFold，避免同一地点的不同土壤泄漏。回归分支使用 PLS 和 Ridge。纹理分支的监督信号不是直接预测 11 个点，而是先把每条训练曲线编码成 Weibull 曲线的两个参数 (ln b, c)。Weibull 曲线 F(d) = 100·(1 − exp(−(d/b)^c)) 的两个参数足以刻画一条平滑单调的级配曲线，而"用最小二乘拟合参数"会在细粒端欠权，因此我们用的是直接最小化比赛指标来得到每个样本的 (ln b, c)，网格粗搜打底、再 Nelder-Mead 精修。Ridge 用五维 DoG 特征预测这两个参数，每张照片按 1/照片数 加权，确保照片多的样本不会在训练里喧宾夺主，样本内取曲线平均而非参数平均。

```python
from sklearn.cross_decomposition import PLSRegression
```

SAM 部分的想法很直白：训练集几乎没有卵砾石，没有任何模型能从训练数据里学会"这堆石头占 30%"，但大石块是可以用分割模型直接测量出来的。我们把全分辨率的高清测试照片压到 2 像素/毫米，裁掉四周 12% 的边缘，用 SAM 自动生成候选掩膜，再按面积从大到小筛掉过小、过大、被大石头盖住或不够圆的掩膜，用掩膜点坐标的协方差算出长轴，统计长轴大于 63 mm、20 mm 的石块面积占比 A63 与 A20。面积并不等于质量，我们只用一个全局系数 k，让训练样本 H374（唯一既有全分辨率照片又有可见石头的训练样本）的 20 mm 点能被凑准，k = (100−F20(H374))/(100·A20(H374))。当某个样本 A63 ≥ 2% 时，就把 63 mm 与 20 mm 两个点改写为 100−k·A20 与 100−k·A63，并把 20 mm 以下的点按比例压缩，保持细粒段的曲线形状。

我们在训练中尝试不同 ppm 对齐、不同 DoG σ、不同融合权重以及在细粒端的多种修复配方。本地代理误差采用对数面积代理。

### 2.4 测试指标
我们保留第七版提交作为最终结果。历史记录如下：

- 初始提交：75.52636
- 第七版融合方案：36.03689
- 后续使用 SAM 专科颗粒分割与单土壤校准的尝试：38.74508

在第七版方案的时间线上，我们用地点留出的 OOF 协议跟踪效果：把 24 个训练样本按 15 个地点分组，每一折留出一个完整地点，避免同地点的样本同时出现在训练和验证里。在这个协议下，基础融合模型的本地地点 OOF 约为 39.15594，跨手机 OOF 约为 43.82539。跨手机诊断更进一步：固定留出地点，用摩托罗拉照片训练、三星照片预测，再反向做一遍，两个方向都评估，只有同时拥有两种手机照片的样本才计入。这是比混合手机训练更严格也更贴近真实测试场景的协议，但它毕竟无法替代对真实 iPhone 域的一条完整验证。

SAM 粗颗粒校正在本地验证上有所改善，但公开分数反而上升。例如粗糙点得很集中的 ImageGrains 分支实验曾把地点 OOF 从 39.15594 压到 37.37781，看似诱人，可细细拆开就发现问题：净提升中的约 57.6% 来自 H374 一个样本，有 18 个样本改善、6 个变差；把模型选择也嵌套进验证后，OOF 变成了 38.60771，收益只剩约 1.4%；更危险的是某个测试样本在 20 mm 处的改前后预测差了约 40 个百分点，这个改动幅度远超证据支持力度。最终带上全部粗颗粒分支的 CSV 拿到 38.74508，比第七版差了 2.70819。我们认为公开集相机分布与训练不同，过度依赖可见面积会高估粗粒质量，单一聚合的公开分数也无法告诉我们具体是哪个测试样本出了问题。DINOv2 特征在跨设备泛化上更稳健，Ridge 对异常值不敏感，PLS 能捕捉曲线低秩结构。

预测流程最终为：读取原始照片 → 物理尺度对齐与 JPEG 处理 → 提取 DoG 与 DINOv2 → 地点交叉验证 → 应用 SAM 校正 → 导出 CSV。所有照片的特征均缓存，避免重复推理，缓存键是原图 SHA256 加特征配方签名，只要图片或配方一变就会自动失效。整条流程纯 CPU 可跑，本地完整运行一遍大约 37 秒，不需要租 GPU 或调用付费预测 API。我们在本地使用 EMD 加权评估，确保单调约束始终满足，并且在导出提交前逐项断言模板顺序、数值有限性、上下界与末位 100%。

## 三、总结
本文中我们完成了一个从图像到土壤粒径分布的完整建模流程。我们首先进行了 EDA，了解了 24 个训练土壤的曲线分布和相机差异，发现在对数坐标下曲线低秩且地点效应明显；其次清洗了文件名去重音模糊匹配问题，并统一了不同手机的物理尺度 ppm，把尖锐的测试照片压到训练照片的分辨率与 JPEG 质量再做纹理比较；接着构建了 DoG 纹理特征与冻结 DINOv2 语义特征的双分支，纹理分支用 EMD 驱动的方式把标签编码成 Weibull 参数并交给 Ridge 拟合，视觉分支用 PLS 直接回归 11 点曲线，结合地点分组交叉验证与跨手机诊断，最后通过 SAM 粗颗粒校正微调但控制过拟合。最终我们在公开榜单上取得了 36.03689 的成绩，较初始 75.52636 有显著提升，而失败实验 38.74508 也提醒我们跨设备泛化需谨慎，避免过度依赖可见面积估计。我们最大的教训是：本地指标一涨就提交是危险的，要紧的是弄清楚提升集中在几个样本、验证是否覆盖了部署中的每一个分支。该方案在 CPU 上可复现，特征缓存和物理尺度对齐是关键工程实践。
