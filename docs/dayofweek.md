# Day of Week：预测用户下一次访问是星期几

## 一、比赛简介

### 1.1 比赛背景

这个比赛的数据来自一门时间序列课程的练习赛，题目非常直白：给你 30 万个用户在过去 **1099 天**里每一次访问网站的日期，让你猜每个人在 1099 天之后**下一次访问会落在星期几**。

听起来像个脑筋急转弯，因为数据里只有「第几天」，根本没有「星期几」这个标签。比如某人的记录是 `3 10 18 42 49 ...`，这些数字只是从第一天开始数的天数编号。要把它变成星期几，需要我们自己定一个起点：把第 1 天当作星期一，那么第 1、8、15……天都是星期一，以此类推。

难点主要有三个：

1. **数据只有日期编号**，星期几是隐藏的，需要自己用「模 7」换算；
2. **每个人的作息不同**，有人每周一三五来，有人只在周末来，不能用一个统一的规律套所有人；
3. **未来不可见**，我们只能从历史里找重复出现的周期。

### 1.2 比赛目标

训练文件 `train.csv` 有两列：

- `id`：用户编号，从 1 到 300000；
- `visits`：这个用户所有访问过的日期编号，用空格分隔，取值 1～1099。

比赛要求我们为**每一个** `id` 预测 1099 天之后的下一次访问是星期几，输出文件 `solution.csv` 有两列：

- `id`：用户编号；
- `nextvisit`：预测的星期几，取值 1～7（1 代表星期一，7 代表星期日）。

这里有个容易看漏的地方：比赛并没有单独给我们一份「没有答案的测试集」。我们要预测的 30 万个用户，就是训练文件里的这 30 万个用户，只不过要预测的是他们记录结束之后的那一天。这相当于让我们「接着历史往下写一天」。

### 1.3 评价标准

评价指标是**准确率（accuracy）**：预测对星期几的用户数，除以总用户数。因为只有 7 个候选答案，随便瞎猜的准确率是 1/7 ≈ 0.143。分数越高越好，满分是 1.0。

别小看 0.143 这个基线——如果我们的模型只有 0.15，说明它几乎没学到任何东西；能稳定做到 0.23 以上，就已经明显超过瞎猜了。

## 二、解题过程

整场比赛我们走的是「先看懂周期性，再用手工统计量做预测，最后拿神经网络做对照」的路线。下面按数据探索、数据清洗、模型训练与调参、测试与报告四步来讲。

### 2.1 数据探索（EDA）

我们首先把文件读进来，确认行数和列的格式：

```python
import pandas as pd
import numpy as np

# 读训练文件：只有 id 和 visits 两列
df = pd.read_csv("../input/train.csv")
print(df.shape)          # (300000, 2)
print(df.head())

# visits 是空格分隔的字符串，先切成整数数组，方便后面统计
df["visits"] = df["visits"].apply(
    lambda s: np.fromiter((int(x) for x in s.split()), dtype=int)
)
visits = df["visits"].values
```

用 `wc -l` 数一下文件是 300001 行，去掉表头正好 300000 个用户。每个人的记录长短差别很大：活跃用户有上百次访问，安静的用戶只有几次。这一点很关键——访问次数太少的人，历史里根本没有足够的周期信息，后面只能尽量猜。

接着我们统计所有访问日期对 7 取模的分布：

```python
# 把所有用户的访问日期摊平，看它们落在星期几上
all_weekdays = np.concatenate(visits) % 7
counts = np.bincount(all_weekdays, minlength=7)
print(counts / counts.sum())
```

结果不是均匀的七分之一，而是有明显的起伏。这说明用户整体上偏爱某些日子（比如工作日比周末多），这一点可以当作一个很弱的先验。

最重要的一步是注意到这个除法：

```python
MAX_DAY = 1099
print(MAX_DAY / 7)        # 157.0
print(MAX_DAY % 7)        # 0
```

**1099 正好等于 157 个星期**，一天不多一天不少。这意味着第 1 天、第 8 天、……、第 1094 天是同一个星期几，整个历史刚好是 157 个完整的「周」。于是「下一次访问是星期几」这个问题，就变成了「这个人在第 158 周最可能哪一天来」。

我们再挑一个用户，把他的访问日期换算成星期几画出来：

```python
import matplotlib.pyplot as plt

# 取一个用户，把日期编号转成 0~6 的星期下标
days = visits[0] % 7
plt.plot(days, "o")
plt.yticks(range(7), ["一", "二", "三", "四", "五", "六", "日"])
plt.title("某个用户的访问星期分布")
plt.show()
```

图上能看到这个人的点集中在两三个固定的行上——他不是随机来的，而是有固定的「每周习惯」。这正是我们后面所有方法的基础：**对每个用户，统计他在星期一至星期日各来过多少次，挑最像的那一天。**

### 2.2 数据清洗

这份数据的清洗非常简单，因为字段只有两个，也没有真正的缺失值。我们做了三件事：

**第一，把字符串变成数字数组。** 原始 `visits` 是一串用空格隔开的字符，直接算没法算，必须先转成整数数组。这就是 2.1 里那句 `np.fromiter`。

**第二，检查异常标签。** 材料里提到，公开数据中不存在「没有下一次访问」的用户（也就是没有标签为 0 的样本），所以不用考虑「这个人再也不来了」这种情况，可以放心地假设每个人都有一个下一次访问日。

**第三，为训练样本设一个最低门槛。** 我们的模型（尤其是神经网络）需要一段历史才能看出规律，材料里的 LSTM 方案要求至少 35 天的记录（28 天输入 + 7 天输出），加权方案则要求至少 `28 + 7` 天。记录太短的用户保留在提交里，但不参与训练，预测时退回一个全局的先验。

然后我们把每个人的历史整理成一张「周 × 星期」的表：

```python
MAX_DAY = 1099
WEEKS = MAX_DAY // 7          # 157

def to_week_matrix(visit_days):
    """把一个人的访问记录变成 157 行 × 7 列的 0/1 矩阵。
       行是第几周，列是星期几（0=周一 ... 6=周日）。"""
    mat = np.zeros((WEEKS, 7), dtype=np.int8)
    for d in visit_days:
        week, weekday = divmod(d - 1, 7)   # d-1 让第 1 天落在第 0 周第 0 列
        mat[week, weekday] = 1
    return mat
```

`divmod` 一次就能同时算出「第几周」和「星期几」，比写两次除法干净。这张表是后面所有统计的原材料。

### 2.3 模型训练与超参数调优

我们试了两条路线，一条是纯统计，一条是神经网络。

**路线一：条件概率。** 直觉是这样的：如果一个人过去 157 周里，星期四来的概率最高，但最近几周他改成了星期三来，那我们就把两个信息合起来。材料里的做法是，先算每个星期几的到访概率 `p[i]`，再算「这周第一次来恰好是星期 i」的概率：

```python
# 每个用户每个星期几的到访频率
week_visits = np.stack([to_week_matrix(v) for v in visits])   # (N, 157, 7)
weekday_prob = week_visits.sum(axis=1) / WEEKS                # (N, 7)

preds = []
for probs in weekday_prob:
    next_prob = np.zeros(7)
    for i in range(7):
        # 这周前 i 天都没来，第 i 天来的概率 = 当天概率 × 前面都没来的概率
        p = probs[i]
        for j in range(i):
            p *= (1 - probs[j])
        next_prob[i] = p
    preds.append(np.argmax(next_prob) + 1)   # +1 转回 1~7
```

`next_prob[i]` 的算法值得解释一下：它假设「星期几来」这件事每天独立，那么「星期一没来、星期二没来、星期三来了」的概率就是 `(1-p0)*(1-p1)*p2`。这相当于把「下一次」理解成「这周里第一次出现的那一天」。

**路线二：加权众数（我们最终采用的主线）。** 条件概率法把所有 157 周一视同仁，但人的习惯会变，最近几周应该更有分量。于是我们给每一次访问加一个随时间增长的权重，再用加权众数挑出星期几：

```python
from sklearn.utils.extmath import weighted_mode

# 日期编号 -> 星期下标（0~6）
weekday_index = [(d - 1) % 7 for d in range(1100)]

# 第 i 天属于第 (i+6)//7 周，权重取「周序号 ^ 1.5」
# 越靠后的周权重越大，幂次控制衰减的陡峭程度
powers = [((i + 6) // 7) ** 1.5 for i in range(1100)]

def predict_weighted(visit_days):
    days = [weekday_index[d] for d in visit_days]
    wts = [powers[d] for d in visit_days]
    # weighted_mode 返回加权后出现次数最多的那个星期
    res = weighted_mode(days, wts)[0][0]
    return int(res) + 1

answer = [predict_weighted(v) for v in visits]
```

这里的超参数只有一个：幂次 `p`。作者在材料里比较了 1、1.5、1.7、2 四个取值，结论是 **1.5 最好**：太小（比如 1）等于把早期和近期的习惯混在一起，太大（比如 2）又会让模型只顾最近几周，被偶然的几次访问带偏。我们沿用了 1.5。

顺带说一句，材料里还有另一种加权思路：权重从 1 开始，每来一次加 0.1。它和幂次加权本质相同，都是「越近越重要」，只是曲线形状不同。

**路线三：LSTM（拿来当对照）。** 我们还按材料实现了把最近 40 天的访问做 one-hot 编码（每天一个 7 维向量），送进两层 LSTM，最后接 7 类 softmax：

```python
from keras.models import Sequential
from keras.layers import LSTM, Dense
from keras.optimizers import Adam

sz = 40                     # 用最近 40 天当输入
model = Sequential()
# 第一层 LSTM 返回整个序列，第二层只返回最后一步
model.add(LSTM(7, activation="tanh", return_sequences=True,
               dropout=0.2, input_shape=(sz - 1, 7)))
model.add(LSTM(7, activation="tanh"))
# 输出 7 个星期几的概率
model.add(Dense(7, activation="softmax"))
model.compile(loss="categorical_crossentropy",
              optimizer=Adam(0.001), metrics=["accuracy"])
```

为了让模型学会「用前 39 天预测第 40 天」，我们把每个用户的序列按 40 天切一段，前 39 天做输入、最后一天的 one-hot 做标签。训练时按序列长度分组，长度不足 40 的在前面补零。

**关于调参。** 我们主要调了两个地方：一是加权方案里的幂次，二是 LSTM 的训练轮数。LSTM 在验证集上的准确率从第 1 轮的 0.226 慢慢爬到第 5 轮的 0.234，之后就基本不动了；再训练也只是在训练集上过拟合。所以我们没有在神经网络上死磕。

### 2.4 模型测试与指标报告

因为我们没有官方的验证集，只能用「把历史的最后几周切掉」的办法造一个：用前 149 周的数据训练，把第 150～157 周当作「未来」，看模型能不能猜中下一周的星期几。材料里的切分点是 `1099 - 8*7 = 1043`，也就是留出最后 8 周。

```python
train_threshold = 1099 - 32 * 7   # 训练截止
test_threshold  = 1099 - 8 * 7    # 验证截止

# 对每个用户，只看截止点之前、以及跨过截止点的那一次访问
# 这样「下一次访问」的标签才是有定义的
```

在这套切分下，LSTM 的验证结果是这样的：

```
Iteration #1   train 0.22647   val 0.22955
Iteration #2   train 0.22871   val 0.23156
Iteration #4   train 0.23083   val 0.23292
Iteration #5   train 0.23146   val 0.23419
```

可以看到训练准确率和验证准确率差不多，都在 0.23 附近，说明模型没有严重过拟合，但也说明 LSTM 能榨出的信息差不多就到这了。对比一下：瞎猜是 0.143，LSTM 是 0.234，提升了六成多，但离「猜得很准」还差得远——毕竟一周有七天，而人的访问又带随机性。

最后我们生成提交文件，注意编号要转回 1～7，id 要写回原始编号：

```python
with open("solution.csv", "w") as f:
    f.write("id,nextvisit\n")
    for i, p in enumerate(answer):
        # i 从 0 开始，原始 id 从 1 开始；p 已经是 1~7
        f.write("{}, {}\n".format(i + 1, p))
```

写完后我们抽查了前几行和行数（300000 + 表头），确认格式和样例一致。

## 三、总结

本文中我们完成了 Day of Week 比赛的一次完整尝试。我们首先通过 EDA 发现了这场比赛的关键事实：1099 天正好是 157 个完整的星期，所以「预测下一次访问是星期几」本质上是「预测这个人第 158 周的作息」。其次我们把每个用户的日期字符串转成整数，再整理成「周 × 星期」的 0/1 矩阵，并给训练样本设了最少 35 天的门槛。接着我们试了两条路线：一条是按星期几的到访概率算「这周第一次来访」的条件概率，另一条是给访问加权（权重随周数按 1.5 次方增长）后取加权众数。然后我们还用两层 LSTM 做了对照，它的验证准确率从 0.226 爬到 0.234 就停住了。最后我们按加权众数生成提交文件，并检查了格式。

这个比赛给我们的最大启发是：**先把数据里的隐藏结构找出来，往往比换更复杂的模型更值钱**。1099 = 157 × 7 这个巧合，一旦被发现，整个问题就从「序列预测」降级成了「统计每个人偏爱星期几」；而 LSTM 花了那么多力气，也只是逼近这个简单统计量的水平。另一个教训是验证集的构造：时间序列不能随机切分，必须按时间往后切，否则「用未来预测过去」，分数会虚高。
