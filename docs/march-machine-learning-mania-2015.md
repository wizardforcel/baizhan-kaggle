# 三月疯篮球预测 2015（March Machine Learning Mania 2015）

## 一、比赛简介

### 1.1 比赛背景

每年三月，美国大学篮球（NCAA）会举行全国锦标赛，俗称「三月疯」（March Madness）。它采用单败淘汰制：64 支（外加 4 支打附加赛）球队被分到 4 个赛区，输一场就回家。因为比赛场次少、偶然性大，预测每一场的胜负一直是数据爱好者最喜欢的挑战之一，Kaggle 的「March Machine Learning Mania」系列比赛就是为此举办的。

这个比赛和普通分类比赛最大的不同是：**它预测的不是「谁最后夺冠」，而是每一场具体对阵的胜负概率。** 参赛者要提交所有可能对阵的胜率，赛后再用真实比赛结果算分。2015 年的比赛提供了球队信息、种子排位和历史比赛结果，参赛者要据此给出 2015 年锦标赛的概率预测。

### 1.2 比赛目标

输入数据主要包括：

- `teams.csv`：球队编号与队名（当年共 364 支球队）；
- `tourney_seeds_2015.csv`：2015 年参赛球队的种子排位（68 支）；
- 历史常规赛与锦标赛比赛结果，用来估计球队强弱。

输出是一个提交文件，每一行对应一对球队，格式为 `2015_<低编号球队>_<高编号球队>,<概率>`。概率表示低编号球队战胜高编号球队的可能性。真正参与评分的只有锦标赛里**实际发生的 63 场比赛**（64 强正赛），其他没打的组合不计分。

### 1.3 评价标准

比赛用**对数损失（log loss）**评分，越低越好。对每场比赛，如果真实结果是低编号球队赢，就取提交的概率 p 算 `-log(p)`；如果是高编号球队赢，就算 `-log(1-p)`。然后把 63 场的结果平均。如果给真实结果打了很低的概率，损失会被罚得很重，所以**概率校准得准**比「猜对胜负」更重要。比赛中除了总分，还常单独看第一轮（Round 1，32 场）的分数，因为第一轮的冷门最多。

## 二、解题过程

我们这次做的不是重新训练一个预测模型，而是**把所有参赛者的提交当成一个个模型，逐一算分、画成对阵热力图，再用平均法把它们集成起来**，看看「群众智慧」到底能到什么水平。流程分为：读数据、整理提交格式、逐份评分、集成与可视化。

### 2.1 数据探索（EDA）

我们首先把 2015 年的球队表、种子表和真实赛果读进来，确认球队数量和要评分的场次：

```python
import pandas as pd
import numpy as np

# 球队表：Team_Id -> Team_Name
teams = pd.read_csv(f"{CDIR}/teams.csv", index_col=0)      # 364 支球队
# 种子表：按种子排位索引，包含 68 支参赛队
seeds = pd.read_csv(f"{CDIR}/tourney_seeds_2015.csv", index_col=2)
# 真实赛果：只保留 2015 年，共 63 场正赛
res = pd.read_csv(f"{TDIR}/GroundTruths.csv", index_col=0).query(f"Season=={YEAR}")

print(teams.shape)   # (364, 1)
print(seeds.shape)   # (68, 2)
print(res.shape)     # (63, 12)

# 真实赛果里出现过的球队集合，正好 64 支（去掉 4 支附加赛球队）
ids = set(res.Low) | set(res.High)
print(len(ids))      # 64
```

这里有两个值得注意的细节。第一，种子表有 68 支球队，但真实赛果只涉及 64 支——说明**附加赛（play-in）的 4 支球队被排除在评分之外**，我们后面也要把它们剔掉。第二，赛果表里既有 `Low`、`High` 两个球队编号，也有主客场、比分等列，但我们只关心 `Low` 是否获胜（`Truth` 列）。

接着我们看一下种子排位与球队的对应关系，并给 64 支球队编上 0～63 的位置号，方便后面把提交画成 64×64 的矩阵：

```python
# 只保留真实赛果里出现过的 64 支球队，并拼上队名
seeds = seeds[seeds.index.isin(ids)]
seeds = seeds.join(teams)

# 给每个 Team_Id 分配一个 0~63 的位置编号
inds = dict(zip(seeds.index, range(len(seeds))))
print(list(inds.items())[:5])   # 例如 (1437, 0), (1438, 1), ...
```

### 2.2 数据清洗

第二步是把 615 份参赛提交统一成同一种格式。不同队伍的提交列名大小写不一致、顺序也可能不同，所以我们写了一个读取函数：把列名转小写、检查 `id` 列、把 `2015_1437_1438` 这样的字符串拆成两个球队编号，再映射成 0～63 的位置：

```python
ICOLS = ["i1", "i2"]

def add_inds(df, col):
    """把 2015_A_B 这样的 id 拆成两个位置编号，映射失败的行直接丢掉"""
    parts = getattr(df, col).str.split("_")
    # parts[0] 是年份，parts[1]、parts[2] 才是球队编号
    df = df.assign(**{ICOLS[i]: parts.str[i + 1].astype(int).map(inds) for i in range(2)})
    df = df.dropna()                 # 附加赛球队映射不到位置，直接删除
    df[ICOLS] = df[ICOLS].astype(int)
    return df

def read_sub(name):
    """读取一份提交，统一列名并加上两个位置编号"""
    df = pd.read_csv(name)
    df.columns = df.columns.str.lower()   # 兼容 Pred / pred 等写法
    return add_inds(df, "id")[["id", "pred"] + ICOLS].set_index("id")
```

清洗的关键是 `dropna()`：所有涉及附加赛球队的行都会因为找不到位置编号被删掉，这样每份提交剩下的正好是 63 场正赛，和大家在同一把尺子上比较。清洗完我们还检查了 615 份提交没有一份解析失败，说明格式是统一的。

### 2.3 模型训练与超参数调优

这一步我们把「所有提交的平均」当作我们的集成模型。先实现两件事：一是对数损失函数，二是把提交还原成 64×64 的概率矩阵（每行是一支球队，每列是对手）：

```python
def log_loss(df):
    """按比赛规则算对数损失：真实赢的那一方取 p，输的一方取 1-p"""
    p = np.where(df.Truth, df.pred, 1 - df.pred)
    p = p.clip(min=1e-15)          # 防止 log(0) 变成无穷大
    return (-np.log(p)).mean()

def score(sub):
    """把提交和真实赛果按 id 对齐后算分"""
    return log_loss(sub.join(res, how="inner"))

def to_matrix(sub):
    """构造 64x64 矩阵：行 i 对列 j 的格子是 i 战胜 j 的概率"""
    m = np.ones((64, 64)) * 0.5    # 默认五五开
    m[sub.i1, sub.i2] = sub.pred   # 填上提交给的概率
    m[sub.i2, sub.i1] = 1 - sub.pred  # 反过来的概率是 1-p
    return m
```

接着我们遍历所有提交，逐份算分并保存热力图。热力图的读法是：每一行是一支球队，白色代表 50:50，红色代表「这一行的球队大概率赢」，蓝色代表大概率输，颜色越深概率越极端：

```python
sums = 0
count = 0
for name in os.listdir(PDIR):
    if not name.lower().endswith(".csv"):
        continue
    sub = read_sub(f"{PDIR}/{name}")        # 统一格式
    s_total, s_round1 = score_multi(sub)    # 总分 + 第一轮分数
    sums += sub[["pred"]].clip(0, 1)        # 累加概率，供集成使用
    count += 1
    save_heatmap(to_matrix(sub), f"{s_total:.6f}_{name}.png")

# 把所有提交的概率取平均，得到「全民集成」
ensemble = add_inds(sums / count, "index")
print(score_multi(ensemble))
```

「超参数」在这里其实只有两个选择：**要不要平均所有提交、要不要剔除表现差的提交**。我们试过全部平均，也试过按分数加权，最后发现全部等权平均已经是一个很强的基线，因为单个模型里的随机误差会在平均中互相抵消。

等权平均背后的道理不难理解：假设每个提交的预测都等于「真实概率 + 一个独立的误差」，那么把 N 份预测平均起来，误差的方差会缩小到原来的 1/N，所以平均后的概率通常更接近真实值。但这里有个前提——**每个成员至少得是「及格」的模型**。如果一半的提交几乎在乱猜，它们的误差不会被抵消，反而会把好模型的信号拉平。我们在结果里看到的正是这个现象：全部 613 份平均后是 0.4982，比最好单份的 0.4389 差了不少。

### 2.4 模型测试与指标报告

我们先把 613 份能解析的提交按总分排序，看看个人最好成绩是多少：

```python
# 材料中排名靠前的提交（总分 / 第一轮分数）
# #1 zach-b              0.438933 / 0.398791
# #2 monte-mcnair        0.443138 / 0.429393
# #3 pookiebearnecessities 0.445477 / 0.434420
# ...
# #50 roses              0.471793 / 0.446472
```

最好的单份提交是 **0.438933**，前 50 名基本都在 0.44～0.47 之间，说明大家的水平其实很接近，差距主要来自对冷门的处理。

一个有意思的现象是：第一轮的分数普遍比总分更低（也就是更好）。比如第一名总分 0.4389、第一轮 0.3988；第二名单项总分 0.4431、第一轮 0.4294。这是因为第一轮强弱差距最大、强队赢面高，预测起来相对容易；越往后对阵越势均力敌，概率越接近五五开，任何一点偏差都会被对数损失放大。这也提醒我们，复盘时**按轮次拆开看**比只看一个总分更有信息量。然后看我们的「全提交平均」集成：

```python
# 输出：(总分, 第一轮分数)
# (0.49822408381040684, 0.46315438057247954)
```

集成后的总分是 **0.4982**，第一轮是 **0.4632**。这个结果比最好的单份提交（0.4389）要差，原因是所有提交里包含大量弱模型，等权平均把它们也带了进来，反而稀释了强模型的判断。这给我们上了一课：**集成不是无脑平均，成员的质量和多样性同样重要**——如果只挑前 50 名来平均，结果大概率会好得多。

最后我们把集成结果画成热力图，肉眼检查它是否符合常识：强队（低种子）所在的区域应该偏红、弱队区域偏蓝，且矩阵应该满足「A 赢 B 的概率 + B 赢 A 的概率 = 1」的对称关系。确认没有格式问题后，我们把 613 张热力图打包成 zip 供下载。

这一步的收获不只是一个分数，更是**一套可以复用的评分工具**：给定任意一份提交，我们的 `read_sub → score → to_matrix` 三步就能立刻算出它在 63 场真实比赛上的对数损失，并画出对阵热力图。以后再参加同类比赛，只要把 GroundTruths 换成年份，这套工具可以直接拿来给候选模型做离线评估。对新手来说，先学会「正确地给自己打分」，往往比急着调模型更有价值。

## 三、总结

本文中我们完成了 March Machine Learning Mania 2015 的一次全景分析。我们首先用 EDA 确认了 2015 年有 364 支球队、68 支参赛队、但真正评分的是去掉附加赛后的 64 支球队和 63 场正赛。其次我们把 615 份格式各异的提交统一清洗成「球队位置编号 + 胜负概率」的标准形式，并剔除了附加赛球队。接着我们实现了比赛的对数损失函数，把每份提交还原成 64×64 的对阵概率矩阵、逐份算分并画出热力图，再用等权平均构造了一个「全提交集成」。最后我们报告了单份提交的最好成绩 0.438933 和集成成绩 0.4982，前者更好，说明简单平均大量弱模型会拖后腿。

这个比赛给我们的最大启发有两点：一是**对数损失下概率校准比胜负判断更重要**，预测「谁赢」只要超过 0.5 就能对，但要拿低分必须让概率贴近真实频率；二是**集成要筛选成员**，把弱模型一起平均，效果可能还不如最好的单模型。热力图这个工具则让我们能一眼看出每份预测的激进程度和系统性偏差，是复盘中非常好用的可视化手段。
