# 不要过拟合！II（Don't Overfit! II）

## 一、比赛简介

### 1.1 比赛背景

「不要过拟合」系列比赛的设定非常反常规：训练数据小得可怜，测试数据却大得吓人。II 代比赛里，训练集只有 **250 行**，每行是 300 个数字化特征加上一个 0/1 标签；测试集却有 **19750 行**。这意味着我们必须用 250 个样本去推断 19750 个未知样本的规律，几乎是把「从极小样本做推断」这件事逼到极限。

更刁钻的是，这 300 个特征是从一个未知的生成过程里来的。事后看冠军分析，真正对标签有影响的特征大约只有 **50 个**，其余 250 个基本是噪声。但参赛时没人知道答案——训练集里几乎所有特征看起来都能「恰到好处」地分开正负样本，这正是陷阱所在：**250 个样本足够让任何模型把训练集记下来，但都不足以反映真实规律**。

所以这个比赛比拼的与其说是「模型的表达能力」，不如说是「谁更克制」：能不能忍住不用复杂模型，能不能认出哪些分数是假象。

### 1.2 比赛目标

- `train.csv`：250 行。第一列 `id`，最后一列 `target`（0 或 1），中间是 300 列特征（命名是 0～299，显然做过脱敏）。
- `test.csv`：19750 行，只有 `id` 和同样的 300 列特征。
- `sample_submission.csv`：`id` + `target`。

我们要为每一行测试数据预测一个 **0～1 之间的概率**（不是 0/1），表示该样本属于类别 1 的可能性。

### 1.3 评价标准

比赛用 **AUC（ROC 曲线下面积）** 评分。AUC 衡量模型的排序能力：随机挑一个正样本和一个负样本，模型给正样本打分更高的概率。1.0 是完美全对，0.5 等于瞎猜。它只看相对顺序、不关心概率绝对值，所以在类别分布不均匀时也比准确率可靠得多。**AUC 越高越好**。

由于训练集太小，本地交叉验证（CV）分数和排行榜（LB）分数经常严重脱节——本地的 0.9 在榜单上可能只有 0.75。如何处理这种脱节，是整个比赛最核心的命题。

## 二、解题过程

我们的路线分两步：先按照「正路子」——强正则化 + 特征选择 + 交叉验证——把常规做法做到位，然后再说说冠军选手是怎么用「探榜」的办法把这个问题的真面目挖出来的。

### 2.1 数据探索（EDA）

我们首先读入数据，看清维度：

```python
import pandas as pd
import numpy as np

train = pd.read_csv('train.csv')
test  = pd.read_csv('test.csv')
print(train.shape, test.shape)   # (250, 302) 和 (19750, 301)
# 训练集 250 行：id + target + 300 个特征
# 测试集 19750 行：id + 300 个特征
```

然后看训练集里特征的大致取值和标签分布：

```python
# 看 5 个特征的统计量，确认是不是标准化的连续值
print(train[['0', '1', '2', '3', '4']].describe())
# 特征大多在 -4 ~ 4 之间，均值接近 0，像是正态分布采样

print(train['target'].value_counts(normalize=True))  # 看正负样本比例
```

一个更关键的分析是**逐个特征单独看 AUC**：用每一个特征单独排序，在训练集上算它的 AUC。正常情况下，有用的特征在训练集上应该有还不错的 AUC；但在这个赛题里，几乎每个特征都能在训练集上达到 0.6～0.7 的 AUC——这就是危险的信号，说明**训练集太小，噪音被当成了信号**。

```python
def fastAUC(x, y):
    """对单特征 x 和标签 y 快速算 AUC"""
    x1 = x[y == 1]; x2 = x[y == 0]
    n1, n2 = len(x1), len(x2)
    r = rank(np.concatenate([x1, x2]))
    return (np.sum(r[:n1]) - n1 * (n1 + 1) / 2) / (n1 * n2)

# 每个特征在训练集上的 AUC（分布会很虚高）
train_aucs = np.array([fastAUC(train[str(i)].values, train['target'].values)
                       for i in range(300)])
print(train_aucs.mean(), train_aucs.std())
```

冠军的探榜数据告诉我们真实世界的对照：**「只靠训练集算出来的特征权重」在训练集上能有 0.984 的 AUC，但在公开榜上暴跌到 0.739**。0.98 → 0.74，这就是 250 个样本下「过拟合到训练集」要付出的真实代价。

### 2.2 数据清洗

表格数据的清洗在这里并不复杂，主要是三步：

1. **丢掉 `id`**。它只是行编号，和目标无关。
2. **确认特征没有缺失值**。这些特征像是机器生成的数值，一般没有缺失。
3. **切出验证集**。250 行里我们切出一小部分做本地验证，剩下的用来训练。

```python
from sklearn.model_selection import train_test_split

X = train.drop(['id', 'target'], axis=1)
y = train['target']

# 250 行太少，验证集切 20% 就只剩 200 行训练，心里要有数
X_tr, X_va, y_tr, y_va = train_test_split(X, y, test_size=0.2,
                                          stratify=y, random_state=42)
```

对 250 个样本来说，验证集本身也很不稳定——换一个随机种子，分数可能差好几个百分点。所以后面我们更依赖**交叉验证**，并时刻警惕「本地分数和榜上分数不一样」。

### 2.3 模型训练与超参数调优

**第一步：用强正则化的线性模型打底。** 在这个赛题里，复杂模型是毒药。决策树、随机森林、SVM 这类模型哪怕再「简单」，在 250 个样本上也几乎必然过拟合。最稳的是**带 L1 惩罚的逻辑回归**——L1 惩罚会强迫模型把大多数特征的权重压成 0，只留下少数关键特征，等于把「特征选择」揉进了训练过程：

```python
from sklearn.linear_model import LogisticRegression
from sklearn.preprocessing import StandardScaler
from sklearn.pipeline import Pipeline

# 标准化：让所有特征在同一个尺度上，正则化才能公平地惩罚
# C 控制正则强度，C 越小惩罚越重；这里用小 C 强制模型克制
model = Pipeline([
    ('scaler', StandardScaler()),
    ('lr', LogisticRegression(penalty='l1', solver='liblinear',
                              C=0.1, random_state=42))
])
model.fit(X_tr, y_tr)
```

**第二步：显式的特征选择。** 除了靠 L1，也可以用**互信息（mutual information）**先挑特征。互信息衡量「知道这个特征后，标签的不确定性减少多少」，对线性/非线性关系都管用。资料里用 `mi > 0.02` 作为门槛，从 300 个特征里筛出了 **79 个**：

```python
from sklearn.feature_selection import mutual_info_classif

mi = mutual_info_classif(X_tr, y_tr, random_state=42)
selected = np.where(mi > 0.02)[0]
print('挑出的特征个数:', len(selected))   # 79

X_tr_sel = X_tr.iloc[:, selected]
X_va_sel = X_va.iloc[:, selected]
```

思路是：把 300 维压到几十维，维度越低，250 个样本还勉强「够用」。

**第三步：不同模型对比。** 资料里做了一个常用对比——逻辑回归、袋装、随机森林、梯度提升各跑一遍交叉验证。结果没有悬念：**线性模型（逻辑回归）全面胜过树模型**。树模型能记住训练集中每个样本的「私密细节」，在样本这么少的时候尤其致命；逻辑回归只有一条直线，想记也记不住，反而占了便宜。资料里这类克制型方案的 CV 分数多在 **0.85～0.89**，个别能到 0.9 上下。

**第四步（冠军的终极操作）：探榜。** 冠军选手没有认命于「本地和榜上对不上」，而是反过来利用榜单。做法分三小步：

1. **探每一个特征**。构造 300 个「只用一个特征做预测」的提交，逐个提交到公开榜，从每次返回的 AUC 里反推每个特征在公开榜上的单独 AUC。虽然费提交次数，但 250 行的训练集信息量太少，大家都在用提交次数探路。
2. **模拟真实数据**。拿到每个特征在「训练集」和「公开榜」上的 AUC 后，用两者加权平均得到每个特征的系数，再按这个系数**模拟生成**300 特征和 50 特征两套数据，用来检验哪一种假设和真实榜单更吻合：
   ```python
   # 用一个已知系数的线性模型生成模拟数据，比较"训练 AUC / 公开 AUC"的比例
   # 和真实榜单是否一致，就能猜出真正的有效特征数
   ```

3. **用 Eureqa 拟合校核函数**。把「探来的 AUC」经过一个符号回归软件学到的非线性函数校正成更准的系数，最后用 `X_test %*% 系数` 线性打分。

### 2.4 模型测试与指标报告

先用常规方案在验证集上评估：

```python
from sklearn.metrics import roc_auc_score

pred_va = model.predict_proba(X_va)[:, 1]
print('验证集 AUC:', roc_auc_score(y_va, pred_va))
```

常规方案的验证 AUC 在 0.85 上下。这里一定要泼冷水：**这个数字几乎注定比榜上高**。资料里「用训练集权重预测」的对照实验显示，训练集 AUC 0.984 / 公开榜只有 0.739；哪怕加了各种正则化，CV 0.89 的方案落地成公开榜也常常只有 0.84 左右（资料里有方案的分数是 Pvt 0.834 / Pub 0.844，另一个是 cv 0.889 / pub 0.865 / pri 0.881）。

冠军方案的最终成绩是：

| 方案 | 公开榜 AUC | 私有榜 AUC |
| --- | --- | --- |
| 假设 300 有效特征 | 0.930 | 0.880 |
| 假设 50 有效特征（备份） | 0.923 | 0.886 |

有意思的是，**公开榜上 300 特征方案更高，私有榜上却是 50 特征方案胜出**——这正是「探榜过度」的缩影：公开榜也是有限数据，多探几次就可能在上面过拟合。冠军最后靠这套模拟+校核拿到了第一名。

提交文件很简单：

```python
submission = pd.DataFrame({
    'id': test['id'],
    'target': model.predict_proba(test[X.columns])[:, 1]   # 用概率，不是 0/1
})
submission.to_csv('submission.csv', index=False)
```

## 三、总结

本文中我们完成了「不要过拟合 II」的完整流程。我们首先通过 EDA 发现：训练集只有 250 行、测试集 19750 行，逐特征的训练集 AUC 虚高到什么都能看两点，这是噪音被误当信号的危险信号。其次我们做了最小量的数据清洗——丢 id、标准化、切出验证集，并特别警惕本地验证分数不可靠。接着我们用强正则化的 L1 逻辑回归、互信息特征选择（300 维筛到几十维）来压制过拟合，交叉验证分数约 0.85～0.89；冠军方案则更进一步，通过向公开榜提交「单特征」探出每个特征的真实 AUC，再用模拟数据反推有效特征数（约 50 个），用 Eureqa 校核系数后线性打分，最终私有榜 0.886。在主线上，我们还对比了一句话：树模型全面输给线性模型，因为小样本下「记住了」不等于「学会了」。

这个比赛给我们最大的启发是：**在极端小样本下，模型的谦虚比聪明更值钱**。L1 正则、特征选择这些「让模型别学太多」的手段，在这里不是锦上添花，而是生死攸关。同时，本地 CV 分数和排行榜分数的巨大鸿沟提醒我们，评估一个模型要时刻想清楚：它到底在学规律，还是在背 250 个样本的答案。
