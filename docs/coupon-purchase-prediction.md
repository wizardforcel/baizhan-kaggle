# 优惠券购买预测（Coupon Purchase Prediction / Ponpare）

## 一、比赛简介

### 1.1 比赛背景

这个比赛来自日本的团购网站 **Ponpare**（ポンパレ，Recruit 旗下的本地生活团购平台）。网站每天会上架一批打折券：餐厅套餐、美容美发、酒店住宿、温泉、体检、摄影……用户看中了就买下来，到店出示券码消费。

对平台来说，最有价值的不是「这张券卖了多少」，而是「**下一个该把哪张券推给这个人**」。推荐得准，用户买得爽，商家也满意；推荐得不准，用户就被满屏不相关的券劝退。

比赛给出的数据正是这个场景的完整日志：

- **用户表**：每个用户的注册日期、性别、年龄、所在都道府县；
- **优惠券表**：每张券的类型（`GENRE_NAME`）、原价（`CATALOG_PRICE`）、折扣价（`DISCOUNT_PRICE`）、展示起止日期（`DISPFROM` / `DISPEND`）、有效期（`VALIDFROM` / `VALIDEND`）、可用星期、所在商圈（`large_area_name` / `ken_name` / `small_area_name`）；
- **购买记录**：谁在哪天买了哪张券；
- **浏览记录**：谁在哪天点开了哪张券，以及最后有没有买。

难点在于**这是一个纯「隐式反馈」问题**。用户不会给券打分，我们只知道「买了」和「看了但没买」，没有「五星好评」这种明确偏好。而且每个用户买过的券少则一两张、多则几十张，绝大多数「用户—券」组合是空的，数据极度稀疏。更麻烦的是原始数据全是日文，光是搞清楚「`ken_name` 是县名」「`DISCOUNT_PRICE` 其实是折扣后的价格」就要费一番功夫。

### 1.2 比赛目标

训练集包含上述几张表；测试集给出 **310 张待推荐的优惠券**（`coupon_list_test`）和 **22782 个用户**（`user_list`）。我们要为**每个用户**挑出 10 张最可能被购买的券，并按可能性从高到低排好序。

提交文件只有两列：

- `USER_ID_hash`：用户编号；
- `PURCHASED_COUPONS`：10 个券编号，用**空格分隔**，顺序有意义（越靠前表示越有把握）。

注意训练集里的券和测试集里的券是**不同的批次**——模型没法靠「记住这张券卖得好」来作弊，必须真的理解「这个用户喜欢什么样的券」。

### 1.3 评价标准

提交格式是「每个用户一串有序的 10 个候选」，这是典型的 **top-K 推荐**评测。这类比赛通常用 **MAP@10**（Mean Average Precision at 10，前 10 名平均精度）来打分：对每个用户，看真实购买的券出现在你列表的第几位，位置越靠前得分越高，一个都没命中就是 0 分，最后对所有用户求平均。

材料里没有写出指标公式，但从两个证据可以确认它是「**按排名给分、越高越好**」：一是提交串的顺序被明确要求（如果只看集合，顺序无所谓）；二是材料里有一份代码的来源链接带着分数标记 `furthermodifiedcosine-007600`，对应的榜单分数约为 **0.0076**。这个数字看起来很小，但在「每人 10 个名额、候选池几百张券」的设定下，已经是不错的水平——**随机猜的期望几乎为 0**。

## 二、解题过程

这场比赛的解法可以概括为一句话：**给每个用户建一张「口味画像」，再拿画像去和每张待推荐券比相似度，取最像的 10 张。** 我们按 EDA、数据清洗、模型训练与调参、测试与指标报告四步来走。

### 2.1 数据探索（EDA）

第一步我们把所有表读进来，先数一遍**每张表缺什么**。这一步看起来枯燥，但在这种多表关联的数据里，缺失情况直接决定了清洗策略：

```python
import pandas as pd
import numpy as np

# 六张表：用户、训练券、测试券、购买记录、浏览记录、商圈
df_user_list = pd.read_csv('../input/user_list_translated.csv')
df_coupon_list_train = pd.read_csv('../input/coupon_list_train_translated.csv')
df_coupon_list_test = pd.read_csv('../input/coupon_list_test_translated.csv')
df_coupon_detail_train = pd.read_csv('../input/coupon_detail_train_translated.csv')
df_coupon_visit_train = pd.read_csv('../input/coupon_visit_train_translated.csv')

# 逐表看缺失值：isna().sum() 每个字段缺了多少条
for name, df in [('train_coupon', df_coupon_list_train),
                 ('test_coupon', df_coupon_list_test),
                 ('user', df_user_list),
                 ('purchase', df_coupon_detail_train),
                 ('visit', df_coupon_visit_train)]:
    print(name, df.shape)
    print(df.isna().sum()[df.isna().sum() > 0])
```

结果里有三个数字特别值得记下来：

- 训练券表的 `VALIDFROM` / `VALIDEND` / `VALIDPERIOD` 各有 **6147** 条缺失，`USABLE_DATE_*` 那九列各有 **7005** 条缺失；
- 测试券表的同类缺失分别是 **96** 和 **101** 条（测试券一共只有 310 张，所以缺得不算少）；
- 浏览记录表的 `PURCHASEID_hash` 缺了 **2710791** 条——这恰恰说明浏览日志里绝大部分是「看了没买」，只有少部分才对应一次真实购买。这个数字本身就是「隐式反馈」最好的注脚。

接着我们看券的类型、商圈、折扣率和用户地区的分布，发现两条对建模很关键的事实：

1. **商圈极度不均衡**。东京、大阪这类大城市的券数量远超小城市，而用户的分布也类似。这意味着「用户在哪」和「券在哪」是否匹配，是最强的信号之一。
2. **折扣率分布偏斜**。大多数券的折扣价集中在某几个价位，少数特别便宜的券拉出一条长尾。

看完了券，再看用户。用户表里 `WITHDRAW_DATE`（注销日期）缺 **21951** 条——绝大多数用户没注销；`PREF_NAME`（都道府县）缺 **7256** 条。这两个字段在推荐里都有用：注销用户不会再来买，地区则决定「推哪儿的券」。

### 2.2 数据清洗

清洗分五步，核心思想是：**把「用户」和「券」放进同一张表，用同一套编码**。

**第一步：合并购买记录和券信息。** 购买记录只有「用户、券、日期、数量」，没有券的属性，所以要把它和券表按券编号拼起来：

```python
# 购买记录 + 券信息，按 COUPON_ID_hash 内连接
df_purchased = df_coupon_detail_train.merge(
    df_coupon_list_train, on='COUPON_ID_hash', how='inner')

# 只保留对推荐有用的列：
# 类型、折扣价、大区、县、商圈 —— 这五样决定了"用户喜欢什么"
features = ['COUPON_ID_hash', 'USER_ID_hash', 'GENRE_NAME',
            'DISCOUNT_PRICE', 'large_area_name', 'ken_name', 'small_area_name']
df_purchased = df_purchased[features]
```

这里我们特意**没有**把原价、有效期、可用星期放进来。原因很实际：这几列缺失太多（6000 多条），填都不知道怎么填；而且它们的信息在「折扣价 + 类型 + 商圈」里已经间接体现了。选特征的第一原则是**能稳定拿到手的才要**，不是越多越好。

**第二步：把测试券也拼进来。** 这是整个方案里最关键的一个技巧。我们需要对「用户」和「测试券」用**完全相同的方式**做独热编码，否则两边的特征对不上。做法是给测试券伪造一个用户 ID：

```python
# 测试券没有购买者，先塞一个假用户 ID，让它们能进同一张表
df_coupon_list_test['USER_ID_hash'] = 'dummyuser'

# 上下拼接：上半是真实购买，下半是待推荐的测试券
df_combined = pd.concat([df_purchased, df_coupon_list_test], axis=0)

# 拼完再按假用户 ID 切回两半
df_train = df_combined[df_combined['USER_ID_hash'] != 'dummyuser']
df_test = df_combined[df_combined['USER_ID_hash'] == 'dummyuser']
```

「先拼后切」的好处是：后面做独热编码时，训练和测试用的是**同一个编码表**。如果分开编码，训练券里出现过的类型在测试券里没有，两边列数就对不上，矩阵乘法会直接崩掉。这个模式在所有「训练集和测试集需要统一编码」的场景里都通用。

**第三步：把数值特征压到合理范围。** 折扣价金额跨度很大（几百日元到几万日元），直接当数值用会让大额券主导相似度。我们取对数把它压缩：

```python
# 折扣价取倒数再取对数：价格越低的券，这个值越大
# 这样"便宜的券"和"贵的券"在数值上被拉近了，不会让高价券一家独大
df_combined['DISCOUNT_PRICE'] = 1 / np.log10(df_combined['DISCOUNT_PRICE'])
```

为什么是 `1 / log10` 而不是直接 `log`？因为目标是「**便宜又好卖**」，除以对数等于把「价格越低越有吸引力」直接编码进特征。材料里另一位选手的 R 版本也用了同样写法。

**第四步：独热编码。** 类别列（类型、大区、县、商圈）必须变成 0/1 列，这样「同一类型」「同一商圈」才会在向量里表现为同一个位置上是 1：

```python
# 类别列做独热编码，dummy_na=False 表示不给缺失单独开一列
df_encoded = pd.get_dummies(df_combined, dummy_na=False)

# 数值列单独拿出来（独热编码会把它们原样保留，但我们要显式控制顺序）
continuous = ['DISCOUNT_PRICE']
df_matrix = pd.concat([df_combined[continuous], df_encoded], axis=1)
```

编码完成后，这张表有 **125 列**（材料里的打印结果是 `22782 rows × 125 columns` 附近的用户画像矩阵），每一行是一个「用户—券」组合，每一列是一个特征。

**第五步：商圈名清洗。** `small_area_name` 里有不少是「新宿, 高田马场, 中野, 吉祥寺」这种**一串地名拼在一起**的写法。我们不做拆分——因为拆分之后「一个人买了新宿的券」并不能说明他喜欢高田马场，反而是「这串商圈组合」本身更接近一家店的真实位置描述。

### 2.3 模型训练与超参数调优

这一节的核心思想是：**我们不训练一个「预测点击率」的分类器，而是直接构建用户向量，用相似度排序。** 这种做法叫**基于内容的协同过滤**，它不需要训练、不需要调参、几行矩阵乘法就能跑完，非常适合这种「用户多、券少、极度稀疏」的场景。

**第一步：把「用户的购买历史」压成一个向量。** 一个用户可能买过 5 张券，每张券对应一行 125 维的 0/1 特征。把这些行**按列求平均**，就得到这个用户的「平均口味」：

```python
# 去掉券编号，只留特征列
df_train_features = df_train.drop('COUPON_ID_hash', axis=1)

# 按用户分组求均值：一个用户买过的所有券，平均下来就是他的偏好向量
# 比如他买的 5 张券里有 3 张是"美食"，那么"美食"这一列就是 0.6
df_user_profiles = df_train_features.groupby('USER_ID_hash').mean()

print(df_user_profiles.shape)   # 22782 行（每个用户一行），125 列
```

「求平均」这个操作看起来简陋，但它有一个很好的性质：**买得越多，画像越稳**。买过 20 张券的用户，画像里的每个数字都是 20 个样本的平均，噪声被抵消了；只买过 1 张的用户，画像就等于那张券本身，模型会默认「他喜欢的就是这一类」。这与「用户行为稀疏」的现实是对得上的。

**第二步：给不同特征分配不同权重。** 125 列不能一视同仁——「商圈」比「大区」重要得多（同一个县里，新宿和八王子完全是两个世界），「券的类型」也比「折扣价」更能区分人群。所以我们手工设了一组权重：

```python
# 每个特征族给一个权重，数值来自经验：
# 商圈最细、最能定位，给 5；类型和折扣次之，给 2；
# 大区太粗（整个关东），只给 0.5
FEATURE_WEIGHTS = {
    'GENRE_NAME': 2,
    'DISCOUNT_PRICE': 2,
    'large_area_name': 0.5,
    'ken_name': 1.5,
    'small_area_name': 5,
}

def find_appropriate_weight(weights_dict, colname):
    """按列名前缀找到它所属的特征族，返回对应权重"""
    for col, weight in weights_dict.items():
        if col in colname:      # 独热编码后的列名形如 small_area_name_新宿
            return weight
    raise ValueError(f'没有为 {colname} 配置权重')

# 拼成一个对角矩阵：对角线上是每一列的权重，其余位置是 0
W_values = [find_appropriate_weight(FEATURE_WEIGHTS, c)
            for c in df_user_profiles.columns]
W = np.diag(W_values)
```

这个对角矩阵的作用，是在做内积之前**先把每一维乘上权重**。数学上等价于「把特征空间拉长或压扁」：权重大的维度被放大，两个用户/券在这一维上的差异也就被放大。

**第三步：算相似度。** 用户画像矩阵（22782 × 125）乘上权重矩阵，再乘测试券矩阵的转置（125 × 310），就得到每一对「用户—券」的分数：

```python
# 测试券去掉券编号列，只留特征
df_test_features = df_test.drop('COUPON_ID_hash', axis=1)

# (用户数 × 特征数) @ (特征数 × 特征数) @ (特征数 × 券数)
# 结果矩阵的形状是 (用户数 × 券数)，每个格子就是一个"匹配分"
similarity_scores = np.dot(np.dot(df_user_profiles, W), df_test_features.T)

print(similarity_scores.shape)   # (22782, 310)
```

作者把这一步叫「加权余弦相似度」，严格说这里算的是**加权内积**——没有做向量归一化（除以模长）。不做归一化在推荐里其实是有意的：**买得多的用户画像数值更大，内积也更大**，相当于给活跃用户更高的分数。而「活跃用户更可能买券」这个假设本来就成立，所以这不算 bug，反而省了一次归一化。

**第四步：男女分开设权重。** 材料里更进一步的版本发现，男性和女性对不同特征的敏感度不一样，于是干脆准备了两套权重，按用户性别切换：

```python
# 男性：更看重类型和折扣；女性：更看重商圈和有效期
weightm = [2.00, 1.25, 1.25, 1.00, 4.50, 0.625, 0.35]   # 男性权重
weightf = [1.75, 0.75, 1.50, 1.00, 4.50, 0.625, 0.25]   # 女性权重

# 每一列属于哪个特征族，就重复填多少个对应权重
# （这里只列出前四组，后面还有 DISPPERIOD、VALIDPERIOD、USABLE_DATE 三组）
Wm = np.diag(np.concatenate([
    np.repeat(weightm[0], 13),   # GENRE_NAME 有 13 个类型
    np.repeat(weightm[1], 1),    # DISCOUNT_PRICE 1 列
    np.repeat(weightm[2], 1),    # DISPPERIOD 1 列
    np.repeat(weightm[3], 9),    # large_area 9 个大区
    np.repeat(weightm[4], 55),   # small_area 55 个商圈
]))
```

这组数字是作者在榜单上反复试出来的「超参数」——在这个没有训练过程的方案里，**唯一能调的就是这些权重**。它的调法很朴素：改一个权重、提交一次、看榜单分数涨没涨。这也解释了为什么一个「不需要训练」的模型还能分出男女两版。

**第五步：把浏览记录也用上。** 只买过 1 张券的用户画像太单薄，但「他点开过什么」同样是信号——看了 20 次却只买 1 次，说明他确实对那类券有兴趣。所以我们把浏览记录也加进画像，但打了个很低的折扣：

```python
# 只保留"看了但没买"的浏览记录（买了的已经在购买表里了，避免重复计算）
visit = df_coupon_visit_train[df_coupon_visit_train['PURCHASE_FLG'] != 1]
visit = visit[['VIEW_COUPON_ID_hash', 'USER_ID_hash']]

# 浏览记录动辄 271 万条，必须分块处理，否则一次性 merge 会爆内存
couponVisitFactor = 0.005   # 一次浏览只算 0.005 次购买
for start in range(0, len(visit), 100000):
    chunk = visit.iloc[start:start + 100000]
    # 把浏览过的券换成它的特征向量，乘上折扣系数后累加到用户画像
    ...
```

这个 `0.005` 的系数非常小，说明作者的判断是：**浏览几乎不算数，购买才算**。但 0.005 乘以几十次浏览，也能给出一点点方向上的偏移——对于「一张没买过的冷启动用户」，这点偏移就是全部信息。

### 2.4 模型测试与指标报告

**排序取前 10。** 有了 22782 × 310 的分数矩阵之后，剩下的工作就是「每个用户取分数最高的 10 张券」：

```python
def get_top10_coupon_hashes_string(row):
    """给一个用户的 310 个分数，返回排好序的前 10 个券编号字符串"""
    # 分数从小到大排序，取最后 10 个（即最高的 10 个），再反转成从高到低
    sorted_row = row.sort_values()
    return ' '.join(sorted_row.index[-10:][::-1].tolist())

# 对每一行（每个用户）应用这个函数
output = df_results.apply(get_top10_coupon_hashes_string, axis=1)
```

这里有一个很容易踩的坑：`sort_values()` 默认是**升序**，最高分在最后。如果忘了 `[::-1]` 反转，提交的 10 个券顺序就完全颠倒了——集合是对的，但第一名变成最后一名，MAP@10 会掉一大截。这类「顺序敏感」的错误在推荐比赛里非常常见，交卷前必须抽查几行。

**组装提交文件。** 最后把用户 ID 和券串拼成两列：

```python
df_output = pd.DataFrame({
    'USER_ID_hash': output.index,
    'PURCHASED_COUPONS': output.values
})

# 用户表是主表：即使某个用户一个候选都没有，也要在提交里占一行（留空串）
df_output_all = pd.merge(df_user_list[['USER_ID_hash']], df_output,
                         how='left', on='USER_ID_hash')

# index=False：提交文件不要行号
df_output_all.to_csv('submission.csv', index=False)
```

`how='left'` 这一步不能省。如果某个用户完全没有历史，我们的画像全是 0，算出来的分数也全是 0，`sort_values` 之后会随便取 10 张。虽然这 10 张基本不可能命中，但**行数必须齐全**，缺行可能导致整个提交被判格式错误。

**指标结果。** 材料里这套「用户画像 + 加权内积」的方案对应的榜单分数约为 **0.0076**（来自代码来源链接里的 `007600` 标记）。单看这个数字很小，但要理解它的尺度：**每个用户只能提交 10 个券，而候选池有 310 张**，即使完全随机地猜，命中率也只有 10/310 ≈ 3%，再考虑「真实购买的券往往只有一两张」，随机策略的 MAP@10 几乎为 0。0.0076 意味着模型确实找到了一部分真实偏好。

另一个可以对照的观察：材料里还试过用 **Surprise 库**里的 SVD、SVDpp、SlopeOne、NMF、KNN 等一系列矩阵分解模型来做同样的任务。那条路线的做法是把「用户—券」看成评分矩阵，用 `PURCHASE_COUNT` 的对数当评分，再对 22782 × 310 的所有组合逐一预测。它的问题很明显：**SVD 这类模型需要每个用户有足够多的历史才能学到隐向量**，而这个数据集里绝大多数用户只买过个位数张券，矩阵分解基本学不动；而且 700 万次 `model.predict` 单条调用，速度也慢得多。所以最终我们采用的是相似度方案，矩阵分解只作为对照。

## 三、总结

本文中我们完成了 Ponpare 优惠券购买预测的完整流程。我们首先用 EDA 摸清了六张表的关系：券表有 6147 到 7005 条有效期和可用日的缺失，浏览日志里 271 万条记录没有购买编号（说明绝大多数浏览都没成交），用户表里有 21951 人没有注销日期、7256 人没填地区，并且确认了「商圈」是最细、最有区分度的特征。其次我们做了五步清洗：把购买记录和券表按券编号合并、给测试券塞一个假用户 ID 后与训练数据拼成一张表（保证两边编码一致）、把折扣价变换成 `1/log10`、对类别列做独热编码、最后按假用户 ID 切回训练和测试两半。接着我们用「用户购买历史按列求平均」构建 22782 个用户的画像，手工给类型、折扣、大区、县、商圈配置了不同权重，用加权内积算出「用户 × 310 张券」的分数矩阵，并把 271 万条浏览记录以 0.005 的折扣系数累加进画像；最后对每个用户取分数最高的 10 张券、反转成从高到低的顺序，用左连接补齐所有用户后写成提交文件，取得约 0.0076 的榜单分数。

这个比赛给我们最大的启发是：**推荐系统不一定非要「训练」一个模型。** 当数据稀疏到每个用户只有几条记录时，矩阵分解这类「学隐向量」的方法根本没有足够的样本可学；反倒是「把历史行为平均成画像、再按相似度排序」这种朴素做法又稳又快。而在这条路线上，**真正决定分数的是特征权重**——模型没有参数可调，那 5 个手工权重就是全部的超参数。另外，处理多表数据时「先拼接、后编码、再切回」这个套路，能避免训练集和测试集编码不一致这类隐蔽的 bug。
