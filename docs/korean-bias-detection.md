# 韩语偏见检测（Korean Bias Detection）

## 一、比赛简介

### 1.1 比赛背景

社交媒体上的评论里经常藏着对某些群体的偏见。比如一句话表面上在聊天气，实际上在贬低女性，或者把某类人归为「其他人」。这类文本在韩语里尤其难识别，因为敬语、缩略语和网络用语很多。

这个比赛提供了一批韩语评论，要求参赛者判断每条评论里有没有偏见、属于哪一种偏见。比赛材料里可见的标签有三类：`none`（没有偏见）、`others`（针对其他群体的偏见）、`gender`（针对性别的偏见）。这是一个典型的多分类文本任务。

主办方在比赛里通常会提供训练集、测试集和提交样例。本次我们拿到的材料只包含一份推理脚本，说明作者使用了一个已经训练好的开源模型直接对测试集打分，而不是从零训练。

### 1.2 比赛目标

输入是一批韩语评论，主要字段是 `comments`。输出是每条评论的偏见类别，取值为 `none`、`others`、`gender` 之一。测试文件名为 `test.bias.no_label.csv`，顾名思义，测试集没有标签列，需要我们自己预测后写进提交文件。

提交文件的格式是保留原始行，并增加一列 `label`（数字编码）。比赛方通过比对预测标签和真实标签来打分。

### 1.3 评价标准

材料里没有直接写出指标定义，只交代了标签到数字的映射：`none→0`、`others→1`、`gender→2`。从任务类型看，这是不平衡的多分类问题，通常会用宏平均 F1（macro F1）来评估，因为宏平均会让每个类别权重相同，不会因为 `none` 样本多就掩盖少数类别的表现。下面我们按「分类指标、越高越好」来理解，不编造具体分数。

## 二、解题过程

整场比赛我们走的是「预训练语言模型 + 直接推理」的路线：不自己训练模型，而是加载别人已经微调好的 KcELECTRA 偏见分类模型，用 `transformers` 的 `pipeline` 批量预测，再把字符串标签映射成比赛要求的数字。下面按 EDA、清洗、模型、测试四步说明。

### 2.1 数据探索（EDA）

第一步是把测试集读进来，看看列名、行数和评论长度：

```python
import pandas as pd

# 读取测试集，文件名说明它没有标签列
df = pd.read_csv('../input/korean-bias-detection/test.bias.no_label.csv')

# 先看形状和前几行，确认 comments 列存在
print(df.shape)
print(df.head())

# 看评论长度分布，判断有没有超长文本
df['length'] = df['comments'].astype(str).str.len()
print(df['length'].describe())
```

我们重点关注两件事：一是 `comments` 列有没有缺失，二是评论长度有没有超过模型的最大输入长度（KcELECTRA 通常限制在 512 个 token 左右）。如果评论特别长，`pipeline` 会截断，尾部信息会丢失。

接着我们统计标签的分布。这里测试集没有标签，所以只能看训练集；材料中没有附带训练集，我们只能根据比赛设定推断三类样本大致是什么比例。为了不编造数字，这里只保留检查代码：

```python
# 如果手上有带标签的训练集，先看类别是否均衡
train = pd.read_csv('../input/korean-bias-detection/train.bias.csv')
print(train['label'].value_counts())

# 看看每个类别下的评论样例，帮助理解标签含义
for label in train['label'].unique():
    print('=====', label)
    print(train[train['label'] == label]['comments'].head(3).tolist())
```

这个检查很关键：如果 `gender` 类样本很少，模型很容易全部预测成 `none`，宏平均 F1 会很难看。理解了类别含义之后，我们才能判断模型输出是否合理。

### 2.2 数据清洗

这份数据的清洗非常轻。我们只做两件事：把缺失评论替换成空字符串，避免 `pipeline` 报错；以及去掉明显的空白字符：

```python
# 缺失评论填成空串，防止类型错误
df['comments'] = df['comments'].fillna('')

# 去掉首尾空白，避免模型把纯空格当成有效输入
df['comments'] = df['comments'].astype(str).str.strip()

# 统计清洗后有多少条空评论
print((df['comments'] == '').sum())
```

我们没有做停用词删除、形态素分析或拼写纠正。原因是 KcELECTRA 这类预训练模型在训练时已经见过大量真实韩语文本，它自己会处理这些变体；人为清洗反而可能破坏模型熟悉的表达模式。这是使用预训练模型和传统 TF-IDF 方案的一个重要区别。

### 2.3 模型训练与超参数调优

我们使用的模型是 `beomi/beep-KcELECTRA-base-bias`，这是社区里基于 KcELECTRA 微调过的韩语偏见分类模型。KcELECTRA 是一种 ELECTRA 架构的韩语预训练模型：它不像 BERT 那样遮住词再猜词，而是让一个小判别器判断每个位置的词是「原文」还是「被替换过」，训练效率更高。

我们没有自己训练，而是直接调用 `transformers` 的 `pipeline`。`pipeline` 把「分词 → 模型前向 → 取最大概率类别」封装成一行调用：

```python
# 安装并升级 transformers，保证模型加载接口是最新的
!pip install -U transformers

from transformers import pipeline

# 加载偏见分类模型，device=0 表示用第一块 GPU
pipe = pipeline(
    'text-classification',
    model='beomi/beep-KcELECTRA-base-bias',
    device=0
)

# 先用一句简单的话测试模型能否正常输出
print(pipe("안녕하세요")[0]['label'])
```

这句测试很重要。`pipeline` 返回的是一个列表，每个元素包含 `label` 和 `score` 两个字段。先跑一句「你好」确认标签名和我们预期的一致，可以避免后面批量推理时才发现标签拼写对不上。

如果显存不够或者没有 GPU，可以把 `device=0` 改成 `device=-1`，用 CPU 推理，速度会慢很多，但结果一样。批量推理时还可以设置 `batch_size` 提高吞吐：

```python
# 批量推理，batch_size 根据显存调整，16 或 32 比较稳妥
# truncation=True 让超长评论自动截断到模型最大长度
results = pipe(
    df['comments'].tolist(),
    batch_size=16,
    truncation=True
)

# 把结果里的字符串标签取出来
df['label_str'] = [r['label'] for r in results]
```

这里我们特意把原始字符串标签先存一列，而不是直接映射成数字。原因是万一模型输出的标签拼写和比赛标签不一致（比如大小写、下划线），我们可以先看一眼再决定怎么映射，不至于把错误悄悄带进提交文件。

**关于调参。** 因为模型是别人微调好的，我们没有训练过程，也就没有学习率、轮数这些超参数可调。真正能调的只有推理侧的 `batch_size`、是否截断、以及要不要对长文本做分段投票。材料里的方案是直接单次推理，我们保持这条主线，没有引入额外复杂度。

### 2.4 模型测试与指标报告

推理完成后，我们先把模型输出的字符串标签映射成比赛要求的数字。材料里给出了明确的映射表：

```python
# 比赛要求的标签编码：none=0, others=1, gender=2
LABEL_DIC = {
    'none': 0,
    'others': 1,
    'gender': 2,
}

# 把字符串标签转成数字
df['label'] = df['label_str'].map(lambda x: LABEL_DIC[x])

# 检查有没有映射失败的（结果为 NaN 的行）
print(df['label'].isna().sum())
```

这一步必须检查 `isna().sum()`。如果模型输出的某个标签不在字典里，`map` 会返回 NaN，提交文件里就会出现空值，直接导致评分失败。材料里的做法是假定标签完全匹配，我们建议在正式提交前一定加上这行检查。

接着看预测分布：

```python
# 看三类各被预测了多少条，判断模型是否过度偏向某一类
print(df['label'].value_counts())
```

如果 `none` 占了绝大多数、`gender` 只有个位数，说明模型在这个测试集上偏保守，宏平均 F1 可能不理想。这时可以考虑调整分类阈值或者用带类别权重的模型，但材料里的基线没有做这一步。

最后生成提交文件。注意提交文件只需要原始列加 `label` 列，不能把中间产生的 `label_str`、`length` 等辅助列一起写进去：

```python
# 只保留提交需要的列，避免多余列导致格式错误
submission = df[['id', 'comments', 'label']]

# index=None 表示不写行号，和样例提交格式保持一致
submission.to_csv('./submission.csv', index=None)

print('finish')

# 快速看前 10 行，确认列名和标签值正确
!head -n 10 submission.csv
```

材料里的脚本最后还打印了 `df.label.value_counts()` 和整个 `df`，用来人工核对结果。我们保留这个习惯：提交前一定肉眼扫一遍前几行。

因为没有本地验证集，我们无法在这里报告一个可信的分数。材料只展示了推理流程，没有给出排行榜成绩。我们能确认的是流程本身是完整的：读取测试集 → 加载模型 → 批量预测 → 标签映射 → 写提交文件。

## 三、总结

本文中我们完成了韩语偏见检测比赛的推理流程。我们首先读取测试集并检查评论长度和缺失情况，其次做了最轻量的清洗——只填空值、去首尾空白，不做形态素分析。接着加载社区微调好的 KcELECTRA 偏见分类模型，用 `transformers` 的 `pipeline` 做批量推理。然后按 `none=0、others=1、gender=2` 的映射把字符串标签转成数字，并检查映射失败和预测分布。最后只保留必要列写出提交文件。

这个方案的最大特点是「站在别人的肩膀上」：不训练、不调参，直接用现成的预训练模型。它适合快速拿到一个可用的基线，但缺点是模型的知识固定在微调时的数据上，遇到新的网络用语或领域漂移时表现会下降。如果要在比赛中冲高分，还需要自己补充训练数据、做领域自适应微调，并按类别调整阈值。

从更广的视角看，语义偏见检测和传统的垃圾邮件检测很像，它们都依赖语言模型对隐含意图的理解。未来还可以尝试把偏见检测和情感分析结合：先判断语气是否负面，再判断负面对象是否指向某个群体。这种两阶段的架构能让模型解释性更强，也更容易在错误案例上做迭代。
