# 俄罗斯国家统一考试选择题（Russian State Exam Multiple Choice）

## 一、比赛简介

### 1.1 比赛背景

**俄罗斯国家统一考试**（俄语：Единый государственный экзамен，简称 ЕГЭ / EGE）是俄罗斯高中毕业生进入大学的主要考试，地位相当于中国的高考。考试科目包括俄语、数学、社会、历史、物理、化学、生物、外语（英语、德语、法语、西班牙语）等。考试中有大量**选择题**：一道题给出 3～6 个选项，考生从中选出唯一正确的一个。

这个比赛的目的，是让参赛者用机器学习或大语言模型来「答题」：给定一道考试题和它的备选答案，预测哪一个选项才是正确答案。这件事对机器来说并不简单。原因有三：

1. **题目涉及真正的学科知识。** 俄语语法、社会学常识、历史事件……光靠字面模式是答不对的，模型必须真的「读懂」题。
2. **题型与语言混杂。** 主体是俄语，但外语科目里混有英语、德语、法语、西班牙语乃至中文；俄语本身又是**高度屈折**的语言，同一个词会因性、数、格变成不同的词形，普通按空格分词的文本处理方法很容易漏掉这些变化。
3. **部分题目带有共享材料。** 一道大题前面会给出一段`context`（阅读材料、地图说明等），后面 3～5 道小题都根据这段材料来提问，答案往往就藏在材料里。

比赛的一些版本还刻意**不提供训练集**，要求参赛者做「零样本（zero-shot）」答题，逼着大家去找外部数据或想办法让模型直接推理。我们在下面介绍的是有 `train.csv` 的标准版本，它也是很多其他版本的基础。

### 1.2 比赛目标

**输入**：每一行是一道选择题，主要字段有：

- `id`：题目编号；
- `exam`：考试类型（如 ЕГЭ 或 ОГЭ）；
- `subject`：科目（如 русский язык、общество）；
- `paper`：试卷编号。同一份试卷由 8～12 道题组成，按 `position`（题号）顺序排列；
- `question`：题干；
- `context`：共享材料。只有部分题目有，语言类题目几乎全靠它；
- `n_options`：选项个数，通常是 3～6；
- `option_1` 到 `option_n`：每个选项的文本；
- `answer`：正确选项的编号（1～n）。这一列只有训练集有。

**输出**：提交文件两列，`Id` 和 `Category`（或者是 `id` 和 `answer`，具体以比赛页面的样例为准，这里我们按材料中的 `Id, Category` 来写）。`Category` 填你选的那个选项的序号。

这里有一个容易踩的坑：**每道题的选项数量不一样**。普通的分类器通常要求「类别数固定」，可这里有的题 3 个选项、有的题 6 个选项，没法直接套用。我们在 2.2 节会介绍一种「把选择题变成判断题」的实用技巧来解决它。

### 1.3 评价标准

比赛用**准确率（Accuracy）**作为评价指标，也就是「答对的题数 ÷ 总题数」。因为是单选题，猜对纯靠运气的期望值大约在 1/4 到 1/3 之间，具体取决于每题选项数。最终排行榜上的分数越高越好，满分是 1.0。

除了总准确率，材料还强调了一个很有价值的观察角度：**按试卷（paper）和科目（subject）拆分来看分数**。一张试卷是「同一科目、同一场考试」的一组题，如果只看一个总分，你会看不出模型其实是「某几个科目很强、其他科目全军覆没」，还是「每个科目都平平」。后面做误差分析时，这个拆分非常关键。

## 二、解题过程

我们的主思路可以用一句话概括：**把「从 N 个选项里挑一个」改造成「判断某个选项对不对」的二分类问题，然后用字符级 TF-IDF 加逻辑回归来打分。** 下面按 EDA、数据清洗、模型训练与调参、测试与指标报告四步说明。

### 2.1 数据探索（EDA）

我们首先把训练集和测试集读进来，看看数据规模和字段：

```python
import glob
import pandas as pd

# 数据在 /kaggle/input 下的某个子目录里，用通配符找到含 train.csv 的目录
P = next(p.rsplit('/', 1)[0] for p in
         glob.glob('/kaggle/input/**/train.csv', recursive=True))
train = pd.read_csv(f'{P}/train.csv')
test  = pd.read_csv(f'{P}/test.csv')
print(train.shape, test.shape)   # 打印行数和列数
train.head(3)
```

接着我们随机抽一道题，把题干和所有选项打印出来，人工确认「正确答案长什么样」：

```python
# 取第 6 行（索引 5）作为样例
r = train.iloc[5]
print(r.exam, '·', r.subject)
print(r.question)
for i in range(1, int(r.n_options) + 1):
    # 在正确选项后面打个标记，方便肉眼核对
    mark = '  <-- correct' if r.answer == i else ''
    print(f'  {i}. {r[f"option_{i}"]}{mark}')
```

输出能看出一个典型结构：题干是一句话，下面是几个长度相近的选项，其中只有一个是正确的。选项之间往往只差一两个词（比如介词、动词变位），这正是俄语题目的难点所在。

然后我们统计各科目的题目数量和**带共享材料的题目比例**：

```python
# 每个 (考试, 科目) 组合各有多少道题，从多到少排
print(train.groupby(['exam', 'subject']).size().sort_values(ascending=False).head(8))

# context 不为空的题目有多少
print('带共享材料的题目：', train.context.notna().sum(), '/', len(train))
```

这一步揭示了两个重要事实：第一，题目分布**很不均衡**，ОГЭ 社会研究和五门外语占了很大比重；第二，有相当一部分题目带有 `context`，尤其语言类题目，答案信息几乎全部在材料里。这意味着：

- 如果模型只学到「社会研究题的常见套路」，它在其他科目上可能很差，而总分会被占多数的那几科「抬」起来，所以我们**必须按科目看分数**；
- 只统计题干和选项的字符 n-gram 会**浪费掉 context**，而 context 恰恰是语言题的关键。

最后我们看一下答案的分布，这是判断「模型有没有超过瞎猜」的基准线：

```python
# 每个选项作为正确答案出现的次数
counts = train.answer.value_counts()
print(counts)
best = counts.idxmax()                 # 出现次数最多的选项编号
print(f'最常见选项：{best}，占训练集 {(train.answer == best).mean():.4f}')
```

如果某个选项占比特别高，那么「永远选这个选项」就会有一个还不错的基线分数。材料里提到，这条「常数基线」在排行榜上能拿到约 **0.288**，这个数字很重要：任何模型的得分如果低于它，说明模型还不如不读题。我们的目标就是要明显超过这条线。

### 2.2 数据清洗

这份数据不需要做删除缺失值、去重这类常规清洗，真正要花心思的是**把数据结构改造成模型能吃的形状**。核心操作是「**展开成（题目，选项）对**」：

对每道题，我们生成 `n_options` 行，每行是「题干 + 共享材料 + 分隔符 + 某个选项」，标签是「这个选项是否为正确答案（0/1）」。这样，不管原题有 3 个还是 6 个选项，都被统一成了同一个二分类问题。预测时，再把同一道题的所有选项分数放在一起，选分数最高的那个。

```python
def pairs(df, labelled=True):
    """把每道选择题展开成若干 (题目, 选项) 对。
    每行文本 = 题干 + context + ' ||| ' + 选项文本，
    标签 y = 1 表示这个选项是正确答案。"""
    rows = []
    for _, r in df.iterrows():
        stem = str(r.question)
        # 如果有共享材料，拼在题干前面，让模型能读到
        if isinstance(r.context, str) and r.context.strip():
            stem += ' ' + r.context
        for i in range(1, int(r.n_options) + 1):
            rows.append({
                'gid': r.id,                                  # 题号，之后按题聚合
                'opt': i,                                     # 选项序号
                'text': stem + ' ||| ' + str(r[f'option_{i}']),
                'y': int(labelled and r.answer == i)          # 测试集没有 answer，全为 0
            })
    return pd.DataFrame(rows)

P_tr = pairs(train, labelled=True)
P_te = pairs(test, labelled=False)
print(P_tr.shape, P_te.shape)
```

这段代码里有两个细节值得说明：

1. **用 ` ||| ` 分隔题干和选项。** 如果不加分隔符，题干结尾的词和选项开头的词会粘连成一个假词，字符 n-gram 会学到噪声。加一个固定符号能把两段文本明确分开。
2. **`gid` 字段保留了原题号。** 预测时我们要按 `gid` 分组选最高分，这个字段必须带着走。

另外，我们**不做转小写、去标点、去停用词**。原因是俄语是屈折语，大小写和词尾变化本身携带语法信息；而且外语题里混着多种语言，统一清洗反而会抹掉区分度。原始文本直接送进字符级向量化即可。

### 2.3 模型训练与超参数调优

**特征提取。** 我们使用**字符级 TF-IDF**（`char_wb`，即按词边界内的字符片段统计）。为什么不用普通的词袋？因为俄语的词形变化太丰富：`книга`（书，主格）、`книги`（属格）、`книгу`（宾格）在按词切分时会被当成三个完全不同的词，而字符级 2～4 gram 能自动捕捉到它们共享的词根 `книг`。同时，字符 n-gram 对英语、德语、法语等混入的语言同样适用，不需要为每种语言单独做分词。

**分类器。** 我们选择**逻辑回归（Logistic Regression）**。它对高维稀疏的文本特征表现稳定、训练快、可解释性好，是一个非常适合做基线的选择。正则化强度 `C=2.0` 是材料里给出的设定，`max_iter=1000` 保证迭代收敛。

```python
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression

# 字符级 TF-IDF：2~4 个字符的片段，最少出现 2 次才保留，最多 6 万个特征
vec = TfidfVectorizer(
    analyzer='char_wb',        # 按词边界内的字符切分
    ngram_range=(2, 4),        # 统计 2、3、4 个字符的连续片段
    min_df=2,                  # 只在至少 2 篇文档里出现过的片段才保留
    max_features=60_000        # 限制特征维度，控制内存
)
X = vec.fit_transform(P_tr.text)

# 逻辑回归：输出「这个选项正确」的概率
model = LogisticRegression(max_iter=1000, C=2.0)
```

**验证集的切法。** 这里有一个很隐蔽但非常关键的坑：因为每道题被展开了多个选项，如果按「行」随机划分训练/验证，同一道题的不同选项会同时出现在两边，验证集等于「见过答案」，分数会被严重高估。正确做法是**按题目分组划分**，保证同一道题的所有选项只落在一边。我们用 `GroupKFold` 做 5 折交叉验证，`groups` 传题号 `gid`：

```python
from sklearn.model_selection import GroupKFold
import numpy as np

scores = []
for trn, val in GroupKFold(n_splits=5).split(X, P_tr.y, groups=P_tr.gid):
    m = LogisticRegression(max_iter=1000, C=2.0).fit(X[trn], P_tr.y.values[trn])
    # 给验证集里每个选项打分
    d = P_tr.iloc[val].copy()
    d['s'] = m.predict_proba(X[val])[:, 1]
    # 同一道题内，选分数最高的那个选项
    pick = d.loc[d.groupby('gid').s.idxmax()]
    # 与真实答案对比，算这折的准确率
    truth = train.set_index('id').answer
    scores.append((pick.opt.values == truth.loc[pick.gid].values).mean())

print('5 折准确率：', np.round(scores, 4), '平均：', round(np.mean(scores), 4))
```

`GroupKFold` 的 `groups` 参数就是「告诉它哪些行属于同一组」，这样划分时同一组不会被拆开。这是做「一道题多个候选」类任务时最常犯的错误之一，值得专门记一笔。

**超参数方面**，我们能调的其实不多：n-gram 范围、`min_df`、特征数上限、逻辑回归的 `C`。我们做过对比，`(2,4)` 的字符 n-gram 配合 `C=2.0` 已经能稳定超过常数基线，进一步扩大 n-gram 范围会让特征维度爆炸、训练变慢，而提升有限。因此我们没有在网格搜索上死磕，而是把精力放在「验证集怎么切才公平」和「按科目分析错在哪」这两件事上——对这类小数据、强先验的任务，评估方法往往比调参更决定成败。

### 2.4 模型测试与指标报告

先在本地用 5 折交叉验证的均值作为参考，确认模型的准确率明显高于「永远选最常见选项」的常数基线。材料给出的对比是：**常数基线在排行榜上约 0.288，TF-IDF + 逻辑回归约 0.325**。这个差距虽然不算大，但它证明了字符 n-gram 确实能捕捉到一些「题目措辞、选项表述」的统计规律，而不是完全靠猜。

然后我们用全部训练数据重新拟合一次，对测试集做预测并生成提交文件：

```python
# 用全部训练数据重新训练
model = LogisticRegression(max_iter=1000, C=2.0).fit(X, P_tr.y)

# 测试集也展开成 (题目, 选项) 对，并打分
P_te = pairs(test, labelled=False)
P_te['s'] = model.predict_proba(vec.transform(P_te.text))[:, 1]

# 每道题选分数最高的选项
pick = P_te.loc[P_te.groupby('gid').s.idxmax()]

# 组装提交文件：列名必须是 Id 和 Category（大小写也要对上）
sub = pd.DataFrame({'Id': pick.gid.values, 'Category': pick.opt.values})
# 按 test 里的 id 顺序重排，保证一行对一题
sub = sub.set_index('Id').loc[test.id].reset_index()
sub.to_csv('submission.csv', index=False)
print(sub.shape)
sub.head()
```

这里 `sub.set_index('Id').loc[test.id]` 这一步是**按测试集的原始顺序对齐**。如果顺序错位，即使每道题都答对了，提交也会整体错位，分数直接归零，所以这种「看起来多余」的重排其实是在保命。

最后我们按科目和试卷拆分，看看模型到底强在哪、弱在哪：

```python
# 把预测结果和测试集按 id 合并
merged = test.merge(sub, left_on='id', right_on='Id')

# 按 (考试, 科目, 试卷) 分组，看每组题量和选 1 号选项的比例
by_paper = merged.groupby(['exam', 'subject', 'paper']).Category.agg(
    n='size',                     # 这组有多少题
    picked_1=lambda s: (s == 1).mean()   # 选 1 号选项的比例
)
print(by_paper.head(12))
```

这一步有两个用途：第一，能看出模型是不是在某些科目上「总选同一个选项」（说明它根本没学会）；第二，由于看不到测试集的标准答案，我们只能看**模型之间的分歧**——如果两个不同模型的预测在某张试卷上差异很大，那这张试卷就是下一步该重点分析的地方。

材料还指出了几条继续提分的明确方向：

1. **真正去读材料（context）。** 字符 n-gram 在语言题上基本用不上 context 里的语义，而语言题的答案恰恰几乎都藏在材料里。要突破 0.325，必须换成能理解长文本的模型。
2. **用更大的题库。** 材料提到有一个约 17.4 万题的公开数据集，其中包含 96,496 道有答案的题和 115,397 道有解析的题。这些都是免费的额外监督信号，比比赛自带的训练集大得多。
3. **按科目分别看分数。** 由于题目被 ОГЭ 社会研究和五门外语主导，一个总分可能完全掩盖模型在某一科上的灾难性表现。

## 三、总结

本文中我们完成了俄罗斯国家统一考试选择题任务的完整流程。我们首先用 EDA 看清了数据结构：每道题有 3～6 个选项，部分题目带共享材料 `context`，科目分布很不均衡，并且「永远选最常见选项」的常数基线在排行榜上约能拿到 0.288。其次，我们把「N 选一」的选择题改造成「判断某个选项是否正确」的二分类问题——每道题展开成多个（题目，选项）样本，用 ` ||| ` 分隔题干与选项，并把 context 拼进题干。接着我们用字符级 2～4 gram 的 TF-IDF 加逻辑回归训练，用按题号分组的 5 折交叉验证避免同题泄漏，最终在排行榜上达到约 0.325，超过常数基线。最后我们生成了 `Id, Category` 格式的提交文件，并按科目、试卷拆分做误差分析，明确了下一步该往「真正读懂材料」和「利用更大题库」两个方向走。

这个比赛给我们最大的启发有两点。第一，**数据形状决定了模型设计**：选项数不固定这件事，用「展开成对 + 组内取最大」就优雅地绕过去了。第二，**验证集必须按组切分**：同一道题的多个选项如果被拆到训练和验证两边，模型等于提前看了答案，分数会虚高得离谱。这两条经验，比多调几个超参数值钱得多。
