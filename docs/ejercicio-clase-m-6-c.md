# 课堂练习：环数预测（Ejercicio Clase M-6-C）

## 一、比赛简介

### 1.1 比赛背景

这是一个西班牙语命名的 Kaggle 课堂练习，标题是 "Ejercicio clase M-6-C"，材料里的两份 notebook 分别叫 `Ejemplo-Base1` 和 `Ejemplo_base`，意思就是"基础示例"。它的目的不是冲排行榜，而是让初学者走一遍**从读取训练数据、到生成提交文件**的完整流程。

从数据本身看，训练表里有一列 `id` 和一列 `Rings`（环数）。代码里打印的说明是 "Edad/cantidad de anillos promedio"，翻译过来是"年龄/平均环数"。这提示我们：任务是用一组测量特征去预测样本的环数，而环数常被当作年龄的代理指标。生物界有个常见现象——某些带壳动物的壳上会留下一圈圈生长纹，环数越多，通常说明活得越久。这个练习就是把"数环数"这件事交给模型来做。

对入门者来说，这类练习的价值在于建立两个习惯：第一，**先做出一个能提交的最小版本**，再谈优化；第二，**提交文件的格式比模型复杂度更先要保证正确**。

### 1.2 比赛目标

训练文件 `train.csv` 包含 `id`、若干测量特征，以及目标列 `Rings`。测试文件 `test.csv` 只有 `id` 和特征，没有 `Rings`。我们要为测试集的每一行预测一个环数，并按下面的格式保存：

| id | Rings |
| --- | --- |
| 测试样本编号 | 预测的环数 |

提交文件名是 `submission.csv`，列名必须是 `id` 和 `Rings`，行数必须和测试集一致。

### 1.3 评价标准

这是一个**回归任务**：输出的是连续数值（环数），不是类别。回归任务通常用误差类指标评分，常见的有均方根误差（RMSE）和平均绝对误差（MAE），两者都是**数值越小越好**。

材料里没有写明这个练习具体采用哪一个指标，所以我们不冒充确切规则。我们按 RMSE 来讲本地检查的方法，因为它最常用、也最容易手算：先算"预测值减真实值"，平方，求平均，再开根号。无论最终是 RMSE 还是 MAE，"预测越接近真实环数，分数越好"这个方向是一致的。

> 小提示：因为训练集里 `Rings` 的均值可以直接算出来，所以哪怕完全不看特征，也能交出一个"所有样本都预测平均值"的版本。这个版本就是**基线**（baseline），后面任何模型都应该和它比。

## 二、解题过程

整篇材料只做了一件事：**算训练集 `Rings` 的平均值，把它填给每一条测试样本**。听起来简单，但它把完整流程跑通了，而且给出了一个所有后续模型都必须超越的参照点。我们按四步讲。

### 2.1 数据探索（EDA）

我们首先把训练表读进来，看看它长什么样：

```python
import pandas as pd

# 读入训练表；路径是 Kaggle 比赛数据的标准挂载位置
df = pd.read_csv('/kaggle/input/competitions/actividad-m-6-c/train.csv')

# 看前几行，确认 id、特征列和 Rings 的排列
df.head()
```

`head()` 的作用不是"看一眼好看"，而是确认三件事：第一，`id` 是不是第一列；第二，目标列是不是叫 `Rings`；第三，特征里有没有明显的文本列或缺失。这三件事决定了后面的代码怎么写。

其次，我们查看表的整体信息：

```python
# info() 会打印每列的非空数量、数据类型和内存占用
df.info()
```

`info()` 的输出能告诉我们：哪些列是数值型（`int64`、`float64`），哪些是文本型（`object`）。数值列可以直接喂给模型；文本列则需要先编码。这个练习的数据比较规整，材料里没有做额外的编码，说明特征以数值为主。

我们还会确认目标列没有缺失。如果 `Rings` 有空值，算平均值时 pandas 会自动跳过空值，但这会让"平均"的含义变得含糊——到底是在多少条样本上平均的？所以训练前必须确认：

```python
# 目标列不能有缺失；有缺失就要先决定删行还是换数据，不能装作没看见
print('Rings 缺失数:', df['Rings'].isna().sum())
print('训练样本数:', len(df))
```

### 2.2 数据清洗

这个练习的清洗只有一步：**把 `id` 从特征里去掉**。

```python
# id 只是样本编号，和环数没有关系；留着它会让模型把"编号大小"当成规律
df = df.drop(['id'], axis=1)
```

为什么一定要删？因为 `id` 往往是从 1 开始递增的整数。如果训练集的 id 和 `Rings` 碰巧存在某种顺序关系（比如数据是按地点或年份排序后导出的），模型就会学到一个假规律："id 越大，环数越多"。到了测试集，id 是另一批编号，这个规律立刻失效，分数就会崩。这种错误叫**数据泄漏**（leakage），是表格比赛里最常见、也最隐蔽的坑之一。

注意：我们只从**训练用的特征表**里删 `id`，**测试表的 `id` 必须保留**，因为提交文件要靠它对齐：

```python
# 测试集单独读入；这里的 id 不能删，提交时要用
test_df = pd.read_csv('/kaggle/input/competitions/ejercicio-clase-m-6-c/test.csv')
print(test_df.head())
```

除了删 `id`，材料没有做缺失填补、异常值处理或标准化。对这个练习来说是合理的：树模型和简单统计对量纲不敏感，而均值基线根本不看特征。**清洗的力度要跟方法匹配**——用一个只输出平均值的模型，却花几小时做特征标准化，就是白费力气。

### 2.3 模型训练与超参数调优

我们训练的"模型"就是训练集 `Rings` 的平均值：

```python
# 在去掉 id 之后的训练表上算目标均值
average_rings = df['Rings'].mean()

# 打印出来，方便人工检查数量级是否合理（比如不应该是负数或几千）
print("Edad/cantidad de anillos promedio:", average_rings)
```

这个数字就是全部"学到的参数"。它有一个很实在的优点：**永远不会预测出离谱的值**。不管测试样本的特征多奇怪，输出都落在训练集的平均环数附近。代价是它完全忽略了样本之间的差异——一只明显更大的个体和一只小个体，会得到同一个预测。

严格说，这里没有"超参数调优"。如果一定要选，只有一个选择：用**均值**还是用**中位数**。材料用了均值。均值会被极端值拉高（比如少数环数特别多的样本），中位数更稳健。对初学者来说，这个对比是一个很好的练习：

```python
# 伪代码：如果想比较均值和 median，可以留出一部分训练样本做验证
# （材料里没有做这一步，这里只说明思路，不报告任何结果）
# from sklearn.model_selection import train_test_split
# tr, va = train_test_split(df, test_size=0.2, random_state=0)
# for stat in ['mean', 'median']:
#     pred = tr['Rings'].agg(stat)          # 用训练部分算统计量
#     rmse = ((va['Rings'] - pred) ** 2).mean() ** 0.5
#     print(stat, rmse)                      # 在验证部分比较谁更低
```

注意这里的关键细节：统计量必须**只在训练部分**上算，再去验证部分评估。如果先在全量数据上算均值再"验证"，验证集的信息就已经混进模型了，算出来的分数会偏乐观。

### 2.4 模型测试与指标报告

接下来生成提交文件。做法是：把测试集的 `id` 原样搬过来，`Rings` 一列全部填同一个平均值：

```python
# 为每条测试样本构造一行：id 来自测试表，Rings 是训练集均值
submission = pd.DataFrame({
    'id': test_df['id'],
    'Rings': average_rings,
})
```

然后保存成 CSV：

```python
# index=False 表示不要把 pandas 的行号也写进文件
submission.to_csv('submission.csv', index=False)
print("Archivo creado, falta subirlo a Kaggle")   # 文件已创建，等待上传
```

保存之后，我们不会立刻上传，而是先做三项检查：

```python
# 1) 行数和测试集一致：少一行、多一行都会被判格式错误
assert len(submission) == len(test_df)

# 2) 列名和顺序正确：必须是 id、Rings
assert list(submission.columns) == ['id', 'Rings']

# 3) 没有缺失值：平均值本身不会是 NaN，但要防训练表空列导致的问题
assert submission['Rings'].notna().all()

# 再把文件读回来，确认磁盘上的内容真的没问题
check = pd.read_csv('submission.csv')
print(check.shape)
print(check.head())
```

为什么要有第 3 步"读回来"？因为 `to_csv` 可能因为编码、索引、分隔符把文件写歪。很多初学者在本地觉得"代码跑通了"，上传后才发现列名多了个 `Unnamed: 0`，或者行数不对。花两秒钟重读一遍，能避免一次无效提交。

**本地指标报告。** 对均值基线，我们可以在训练集上做一个"自我检查"：如果所有样本都预测成均值，训练集上的 RMSE 就等于 `Rings` 的标准差。这不是泛化分数（它没在没见过的数据上测过），但能让我们对误差的量级有个感觉：

```python
# 用均值预测训练集自己，算 RMSE；结果应当正好等于 Rings 的标准差
pred_all_mean = pd.Series(average_rings, index=df.index)
train_rmse = ((df['Rings'] - pred_all_mean) ** 2).mean() ** 0.5
print('训练集 RMSE（均值基线）:', train_rmse)
print('训练集标准差:', df['Rings'].std())
```

这两个数字应该几乎相等（差异只来自分母是 n 还是 n-1）。这个等式本身就是一次很好的理解检验：**"用均值预测"的误差，就是数据的波动本身**。任何模型要想证明自己有用，就必须把误差压到这个数字以下。

至于这个练习最终能拿多少分，材料里没有给出排行榜结果，我们也不编造。我们能确定的是：这个提交在格式上是完整的，在逻辑上是一个合法的基线。

## 三、总结

本文中我们完成了环数预测课堂练习的最小可提交版本。我们首先读入训练表并用 `head()`、`info()` 确认列结构和数据类型，检查目标列 `Rings` 有没有缺失；其次把 `id` 从训练特征里删掉，避免编号被当成规律，同时保留测试集的 `id` 用于对齐；接着用训练集 `Rings` 的平均值作为唯一参数，构造"所有样本同值"的基线预测，并说明了均值与中位数如何用留出集比较；最后生成 `id`、`Rings` 两列的 `submission.csv`，用行数、列名、缺失值三项断言和"读回文件"做校验，并用训练集 RMSE 等于标准差这一性质检查了误差量级。

这个练习给我们的最大收获是：**先把流程跑通，再谈模型**。一个只有平均值的提交，看起来"什么都没做"，但它验证了数据路径、列名、提交格式这些最容易出错的地方。后面换成梯度提升树或线性回归时，只要和这个基线比，就知道新模型到底有没有带来真实的价值。
