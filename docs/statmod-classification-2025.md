# Statmod classification-2025

## 一、比赛简介

### 1.1 比赛背景
Statmod classification-2025 是一个基于 Kaggle 平台的统计建模分类练习。本次 writeup 的代码来源是 Kaggle 用户 hmnshudhmn24 公开发布的 notebook。Kaggle 是一个数据科学竞赛网站，参赛者可以上传代码、分享思路，也可以在比赛中提交预测结果。这个练习的数据以 CSV 文件的形式提供，训练集文件名为 predict_sex_train_utf.csv，测试集文件名为 predict_sex_test_no_answers_no_mv.csv。CSV 是一种用逗号分隔数值的表格文件，可以把它理解成一张 Excel 表，只是用纯文本保存，方便程序读取。

从文件名可以看出，这个任务与性别预测有关。训练集里有一列名叫 Sex，表示每个样本的真实性别；测试集里没有这一列，需要我们用模型去猜。比赛名称中的 Statmod 可以理解为 Statistical Modeling，也就是统计建模。统计建模的核心思想是：先观察一批带有答案的数据，从中总结出特征与答案之间的规律，再用这个规律去判断新数据。对于编程和深度学习入门者来说，这是一个非常合适的练手项目，因为它包含了表格数据分类的完整流程，而且数据量不大，普通电脑也能跑完。

需要说明的是，本次材料只包含了一份 notebook 代码，没有附带比赛页面的详细介绍和排行榜截图。因此下面关于比赛背景的描述，都是根据代码中的文件名、列名、模型和提交格式推断出来的，不会凭空添加材料里没有的内容。

### 1.2 比赛目标
比赛的目标是训练一个分类模型，根据训练数据中已有的特征和 Sex 标签，预测测试集中每个样本的性别。训练数据包含三部分内容：第一列是 Id，相当于每个样本的编号；中间若干列是特征，也就是用来判断性别的依据；最后一列是 Sex，也就是我们要预测的答案。测试数据同样有 Id 和特征列，但没有 Sex 列。模型要做的事情，就是给测试集的每一行补上一个 sex 值。

这里涉及几个入门概念。特征是模型的输入，标签是模型的输出答案。训练就是让模型反复看特征和标签的对应关系，慢慢调整内部参数。预测就是把新的特征送进训练好的模型，让模型给出答案。提交文件必须包含 Id 和 sex 两列，其中 Id 用来告诉平台这一行对应哪个测试样本，sex 是预测结果。代码最后把 sex 转成整数，并检查取值范围；如果模型输出的是 0 和 1，就整体加一，变成 1 和 2。这说明比赛要求的类别编号是 1 和 2，而不是常见的 0 和 1。

### 1.3 评价标准
材料中的代码没有直接写出 Kaggle 平台采用的具体评分公式，也没有打印本地验证分数。我们只能从任务形式和提交格式来判断。代码使用的是 RandomForestClassifier，它的 predict 方法输出的是硬分类标签，也就是直接的类别编号，而不是概率。提交文件里也只有 sex 这一列整数，没有概率列。因此这个比赛大概率使用准确率 Accuracy 作为评价标准，也就是看预测正确的样本占总样本的比例。

准确率的计算非常直白：假设测试集有 100 个样本，模型猜对了 80 个，准确率就是 80%。对于二分类问题，还可以使用 F1 分数、精确率、召回率等指标，它们更关注某一类是否被漏判或误判。如果平台要求提交概率，则通常会使用对数损失 LogLoss，它惩罚的是模型给正确答案分配的概率太低。由于材料只展示了硬标签提交，我们在本文中按照准确率来理解评价标准。需要提醒的是，这一判断属于根据代码做出的合理推断，并非材料中明确写出的官方说明。

## 二、解题过程

### 2.1 数据探索（EDA）

我们首先需要了解 Kaggle 的输入目录里到底有哪些文件，并确认训练集和测试集的文件名与路径。数据探索（EDA）是建模的第一步，意思是先看看数据长什么样，再决定怎么处理。如果不先确认文件位置，后面读取数据时很容易因为路径写错而报错。

```python
import os
# 遍历 Kaggle 的输入目录，打印所有文件的完整路径
# Kaggle 的输入数据都放在只读目录 /kaggle/input 下
for dirname, _, filenames in os.walk('/kaggle/input'):
    for filename in filenames:
        # 把目录名和文件名拼成完整路径，方便复制到读取代码里
        print(os.path.join(dirname, filename))
```

我们首先运行这段代码，把 /kaggle/input 下面的所有文件列出来。os.walk 是 Python 自带的目录遍历工具，它会一层一层地进入子文件夹，把每个目录的路径、子目录名和文件名交给我们。打印结果里能看到 predict_sex_train_utf.csv 和 predict_sex_test_no_answers_no_mv.csv，就说明数据已经挂载好了。接着我们读取训练集，检查列名是否带有多余的空格。很多表格在导出时会在列名前后留下空格，肉眼看不出来，但程序读取后列名就会变成带空格的字符串，后面按列名取数据时就会找不到列。代码用 str.strip() 统一去掉首尾空格，这是一个很小但很实用的清洗动作。

在真正的 EDA 中，我们通常还会查看数据的行数、列数、每一列的数据类型、缺失值数量以及目标类别的分布。比如用 train_df.shape 看形状，用 train_df.info() 看类型，用 train_df.isna().sum() 看缺失值，用 value_counts() 看 Sex 有多少个 1、多少个 2。材料里的 notebook 没有展示这些输出，但它在后续代码中直接处理了目标缺失和特征缺失，说明作者已经通过观察发现了这些问题。EDA 的意义就在于此：先摸清数据的情况，后面的清洗和建模才有依据，而不是盲目套用代码。

### 2.2 数据清洗

其次我们进行数据清洗。表格数据经常存在三类问题：列名不干净、目标列有缺失、特征列有缺失。目标列就是我们要预测的 Sex，如果某一行的 Sex 是空的，这一行就没有答案，模型无法从它身上学习，所以必须删掉。特征列的缺失则可以用填充的方式处理，让模型仍然能够使用这一行。

```python
import pandas as pd
# 读取训练集，文件里带有 UTF 字样，说明文本编码需要留意
train_df = pd.read_csv('/kaggle/input/statmod-classification-2025/predict_sex_train_utf.csv')
# 读取测试集，文件名里的 no_answers 表示没有标准答案，no_mv 表示没有缺失值
test_df = pd.read_csv('/kaggle/input/statmod-classification-2025/predict_sex_test_no_answers_no_mv.csv')

# 去掉列名首尾的空格，防止列名匹配失败
train_df.columns = train_df.columns.str.strip()
test_df.columns = test_df.columns.str.strip()

# 指定目标列名称
target_col = 'Sex'
# 记录删除前的行数，方便后面统计删掉了多少行
initial_rows = train_df.shape[0]
# 删除 Sex 为空的行，因为空标签的样本无法用于训练
train_df = train_df.dropna(subset=[target_col])
# 打印删除的行数，便于确认清洗效果
print(f'删除了 {initial_rows - train_df.shape[0]} 行目标缺失样本')
```

我们接着把特征和标签分开。y 是目标列 Sex，也就是模型要学习的答案；X 是除 Sex 和 Id 之外的所有列。Id 只是编号，和性别没有关系，如果把它当成特征，模型可能会记住编号而不是学习真正的规律，所以要把 Id 去掉。测试集这边，我们单独保存 Id，因为提交文件需要它；其余列组成 X_test。之后对 X 和 X_test 都用 0 填充缺失值。填充 0 是一种简单策略，好处是代码不会因为空值报错，坏处是 0 可能并不符合数据的真实含义。更细致的做法是用均值、中位数或众数填充，但对入门练习来说，先跑通流程更重要。

```python
# 分离标签 y 和特征 X
y = train_df[target_col]
# 去掉目标列和 Id 列，剩下的就是特征
X = train_df.drop(columns=[target_col, 'Id'], errors='ignore')

# 测试集的 Id 单独保存，提交文件要用
test_ids = test_df['Id']
# 测试集去掉 Id 后作为预测输入
X_test = test_df.drop(columns=['Id'], errors='ignore')

# 特征中的缺失值统一填 0
X = X.fillna(0)
X_test = X_test.fillna(0)
```

清洗阶段还有一个关键步骤：处理类别型特征。表格里可能有文字类型的列，比如颜色、地点、类别名称，而大多数机器学习模型只认识数字。pd.get_dummies 的作用就是把一个文字列拆成多个 0/1 列，这种方法叫独热编码。举个例子，如果有一列“颜色”取值为红、绿、蓝，独热编码后会变成三列“颜色_红”“颜色_绿”“颜色_蓝”，原来那一行是红色就写成 1,0,0。这样模型就能把文字当成数字来处理。

训练集和测试集分别做独热编码后，可能出现列数不一致的情况。比如训练集里某个类别在测试集里没有出现，测试集就会少一列；反过来测试集出现新类别，又会多出一列。直接拿去预测会报错，所以代码用 align 把两边的列对齐。join='left' 表示以左边的 X 为准，axis=1 表示按列对齐，fill_value=0 表示缺失的列补 0。经过这一步，X 和 X_test 的特征顺序和数量就完全一致了。

```python
# 对训练集和测试集的类别型特征做独热编码
X = pd.get_dummies(X)
X_test = pd.get_dummies(X_test)
# 以训练集的列为基准对齐测试集，缺少的列补 0，多余的列丢弃
X, X_test = X.align(X_test, join='left', axis=1, fill_value=0)
```

### 2.3 模型训练与超参数调优

接着我们进行模型训练。代码选择了 scikit-learn 中的 RandomForestClassifier，中文叫随机森林分类器。要理解随机森林，先要理解决策树。决策树就像一串判断问题：某个特征大于某个值吗？如果答案是是，就往左走；否则往右走。一路问下去，最后落到一个叶子上，叶子上写着预测类别。单棵决策树容易过拟合，也就是把训练数据背得很熟，但遇到新数据就判断不准。

随机森林的思路是“三个臭皮匠顶个诸葛亮”。它从训练数据中随机抽取多份子样本，每份子样本训练一棵决策树，然后让所有树一起投票，票数最多的类别就是最终答案。因为每棵树看到的数据和特征都略有不同，它们犯的错误不会完全一样，投票之后整体结果会更稳定。代码里 n_estimators=100 表示训练 100 棵树；random_state=42 是随机种子，固定它可以让每次运行得到相同结果，方便复现；n_jobs=-1 表示使用电脑所有 CPU 核心并行训练，加快速度。

```python
from sklearn.ensemble import RandomForestClassifier

# 创建随机森林分类器
# n_estimators=100 表示训练 100 棵决策树
# random_state=42 固定随机种子，保证结果可复现
# n_jobs=-1 表示使用全部 CPU 核心加速训练
model = RandomForestClassifier(n_estimators=100, random_state=42, n_jobs=-1)

# 用清洗和编码后的特征 X 训练模型，标签为 y
model.fit(X, y)
print('模型训练完成')
```

关于超参数调优，材料中的代码只给了一组固定参数，没有做网格搜索，也没有做交叉验证。超参数是模型开始训练之前就要定好的设置，比如树的数量、树的最大深度、每次分裂时考虑多少个特征。调参的常见做法是把训练集再切出一部分作为验证集，或者使用交叉验证，让模型在没见过的数据上试几次，然后比较不同参数组合的分数。本次 notebook 的目标显然是把流程跑通，而不是追求排行榜名次，所以作者选择了随机森林的常用默认配置。对于入门者，先把这条基线跑出来，再尝试把 n_estimators 改大或改小，观察训练时间和效果的变化，是非常好的练习方式。

### 2.4 模型测试与指标报告

然后我们用训练好的模型对测试集进行预测，并生成 Kaggle 要求的提交文件。model.predict 会把 X_test 的每一行送进森林，让 100 棵树投票，最后返回一个类别标签。预测结果先和 Id 拼成一张两列的表，再把 sex 转成整数。接下来代码做了一个很重要的检查：如果预测结果里出现 0，就整体加一，把 0/1 映射成 1/2。这是因为 sklearn 的标签编码有时会把两个类别记成 0 和 1，而比赛要求的是 1 和 2，不转换就会导致提交格式错误。

```python
# 用训练好的模型预测测试集
predictions = model.predict(X_test)

# 把 Id 和预测结果拼成提交表
submission = pd.DataFrame({
    'Id': test_ids,
    'sex': predictions
})
# 把预测结果转成整数，避免出现浮点数
submission['sex'] = submission['sex'].astype(int)

# 如果最小值是 0，说明标签是 0/1，需要整体加一变成 1/2
if submission['sex'].min() == 0:
    submission['sex'] = submission['sex'] + 1
    print('已将类别从 0/1 调整为 1/2')

# 打印前几行，检查 Id 和 sex 是否正确
print(submission.head())
# 保存为 CSV，index=False 表示不把行号写进文件
submission.to_csv('submission.csv', index=False)
print('submission.csv 已保存')
```

最后我们检查提交文件的前几行，确认列名、行数和取值范围都没有问题，然后保存为 submission.csv。到这里，一次完整的分类流程就结束了。关于指标报告，材料中没有展示本地验证分数，也没有展示 Kaggle 排行榜分数，所以我们无法给出具体的准确率数字。如果想自己评估模型，可以在训练集上用 train_test_split 切出一部分数据作为验证集，训练后在验证集上计算 accuracy_score；也可以使用 cross_val_score 做交叉验证。这样得到的分数虽然不是排行榜分数，但能帮助我们判断模型有没有明显的过拟合或欠拟合。需要再次强调，本文只复现材料中出现的步骤，没有虚构任何比赛分数。
